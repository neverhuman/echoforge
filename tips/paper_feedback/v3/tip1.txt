I dug through the repo-side figure generator and the uploaded compiled paper. The paper’s evidence story is genuinely strong, but the figures are currently under-selling it: several are over-packed, one table has a real rendering/data-key bug, and Fig. 7’s caption says “shared scale” while the code normalizes each heatmap independently. The build path matters too: `paper/build.sh` calls `paper/generate_figures.py`, and that file delegates to `paper.generate_figures_major_upgrade_v2.main()`, so the right file to patch is **`paper/generate_figures_major_upgrade_v2.py`**.   The uploaded PDF shows the exact failure modes in the current figures. 

## Highest-priority fixes

The first fix should be **Fig. 6**. The model-card figure shows `PRF/CRF Hz` as `4000/0` and `Chirps` as `0`, while the manuscript’s Table I correctly reports `4000/4000` and `24`. That is a credibility hit because reviewers will assume the model card is wrong, not merely the plotting script. The bug is almost certainly that the figure code reads `band["pulses"]`, while the evidence rows use another key such as `chirps`, `chirp_count`, or `pulses_per_cpi`. The current code computes `pulses = int(_safe_float(band.get("pulses"), 0.0))` and then `crf_hz = pulses / cpi_s`, which explains the zero. 

The second fix should be **Fig. 7**. The caption says the Range-Doppler panels use a shared normalized log-magnitude scale, but `_range_doppler()` currently normalizes every panel separately through `_normalize01(np.log1p(np.abs(rd)))`. Then `imshow(..., vmin=0.0, vmax=1.0)` gives a shared-looking colorbar even though the underlying normalization is per-panel. That is misleading for a diagnostic figure.  

The third fix should be **layout discipline**. Figures 3–5 are trying to carry too many tasks at once. Fig. 3 is simultaneously primary KPI, AP ranking, ROC, PR, and calibration; Fig. 4 mixes AP bars, recall markers, stacked false alarms, near-threshold context, and a large legend; Fig. 5 combines weights and ablation deltas with dense labels. The content is right, but the figures need to be less clever and more audit-like. The manuscript explicitly says the headline KPI is LCB95 Recall@≤1%FPR, while AP/ROC/PR/calibration are supporting diagnostics, so the graphics should visually enforce that hierarchy.

```python
def _wrap(value: Any, width: int = 28) -> str:
    """Small figure-label wrapper that preserves reviewer readability."""
    text = str(value).replace("_", " ")
    return "\n".join(
        textwrap.wrap(text, width=width, break_long_words=False, break_on_hyphens=False)
    )


def _first_number(mapping: dict[str, Any], *keys: str, default: float = float("nan")) -> float:
    """Read the first finite numeric value among several possible evidence keys."""
    for key in keys:
        if key not in mapping:
            continue
        value = _safe_float(mapping.get(key))
        if math.isfinite(value):
            return value
    return default


def _global_normalize01(arrays: list[np.ndarray], low_pct: float = 2.0, high_pct: float = 98.0) -> list[np.ndarray]:
    """Normalize multiple arrays with one shared percentile scale."""
    finite_values = np.concatenate(
        [np.asarray(arr, dtype=np.float64).ravel() for arr in arrays if arr is not None]
    )
    finite_values = finite_values[np.isfinite(finite_values)]
    if finite_values.size == 0:
        return [np.zeros_like(arr, dtype=np.float64) for arr in arrays]

    low, high = np.percentile(finite_values, (low_pct, high_pct))
    if not math.isfinite(float(low)) or not math.isfinite(float(high)) or high <= low:
        low = float(np.nanmin(finite_values))
        high = float(np.nanmax(finite_values))

    if high <= low:
        return [np.zeros_like(arr, dtype=np.float64) for arr in arrays]

    return [
        np.clip((np.asarray(arr, dtype=np.float64) - low) / (high - low), 0.0, 1.0)
        for arr in arrays
    ]


def _friendly_method(name: str) -> str:
    return (
        str(name)
        .replace("locked_candidate", "locked\ncandidate")
        .replace("layered_fusion_c2", "prior\nlayered\nfusion")
        .replace("high_resolution_xku_cuas", "high\nresolution\nX/Ku")
        .replace("tabular_ml_baseline", "tabular\nML\nbaseline")
        .replace("sequence_ml_proxy", "sequence\nML\nproxy")
        .replace("_", " ")
    )


def _friendly_family(name: str) -> str:
    return (
        str(name)
        .replace("rc_fixed_wing", "RC fixed-wing")
        .replace("clutter_only_counterfactual", "clutter-only")
        .replace("multipath_ghost", "multipath")
        .replace("_", " ")
    )
```

## Patch 3: fix Fig. 7’s “shared scale” problem

Replace `_range_doppler()` with this. It returns unnormalized log power, so the whole figure can be normalized once.

```python
def _range_doppler_power(sample: np.ndarray) -> np.ndarray:
    """Return unnormalized log Doppler-vs-range magnitude.

    Range bins are already range-like in the generated sample. Doppler is the
    slow-time FFT over pulses, so do not run a 2-D FFT that also transforms
    the range axis.
    """
    arr = np.asarray(sample)
    if arr.ndim == 3:
        arr = arr.mean(axis=0)
    elif arr.ndim > 3:
        arr = arr.reshape((-1,) + arr.shape[-2:]).mean(axis=0)

    rd = np.fft.fftshift(np.fft.fft(arr, axis=0), axes=0)
    return np.log1p(np.abs(rd))
```

```python
def _save_figure(fig: Any, filename: str) -> Path:
    FIGURE_DIR.mkdir(parents=True, exist_ok=True)
    path = FIGURE_DIR / filename
    metadata = {"Software": "EchoForge paper/generate_figures_major_upgrade_v2.py"}
    description = f"sources={_source_note(filename)}"
    if FIGURE_FALLBACK_NOTES.get(filename):
        description += f"; fallback={_fallback_note(filename)}"
    metadata["Description"] = description

    fig.savefig(
        path,
        bbox_inches="tight",
        pad_inches=0.06,
        dpi=360,
        metadata=metadata,
    )

    if filename not in RASTER_ONLY_FIGURES:
        pdf_path = FIGURE_DIR / f"{Path(filename).stem}.pdf"
        fig.savefig(
            pdf_path,
            bbox_inches="tight",
            pad_inches=0.06,
            metadata=metadata,
        )

    plt.close(fig)
```

```python
#!/usr/bin/env python3
"""Compatibility shim for the current EchoForge paper figure renderer."""

from __future__ import annotations

import sys
from pathlib import Path

REPO_ROOT = Path(__file__).resolve().parents[1]
if str(REPO_ROOT) not in sys.path:
    sys.path.insert(0, str(REPO_ROOT))
```

## Figure-by-figure feedback

**Fig. 1: Signal chain.** The concept is right, but the model-card snapshot is too cramped; long strings spill into the left stack. Use `_wrap()` and widen the right-side boxes. The code currently uses fixed diagram coordinates and long unwrapped `card_lines`, which is exactly why the waveform and receiver-impairment lines collide. 

**Fig. 2: Scenario balance and leakage.** Good content, but too many small panels with tiny labels. Keep split, hard-negative family, leakage checks, and marginal imbalance. Move site/range/aspect/noise into a compact 2×2 or table-style panel, or use only top categories plus “other.” This figure should scream “no leakage, balanced enough,” not “look at eight small bar charts.”

**Fig. 3: KPI.** This is the most important figure. The left primary KPI panel is good, but the rest should be cleaner: use reliability calibration instead of bin counts, make AP ranking horizontal and sorted, keep ROC low-FPR inset, and make the PR legend smaller or outside the axes. The paper’s text already frames LCB95 Recall@≤1%FPR as the headline metric and AP/ROC/calibration as diagnostics, so the figure should follow that hierarchy. 

**Fig. 4: Phase and false alarms.** Add a legend entry for the red fixed-FPR recall line. The right stacked bars should be simplified: show top five methods, top five families, and roll the rest into “other.” The current legend and labels are doing too much.

**Fig. 5: Component weights and controls.** The content is excellent because it makes the locked candidate auditable. But the right panel needs more whitespace and shorter labels. Also add a visual separator between “negative controls” and “positive controls,” because passive-RF-only outperforming the full locked candidate in AP/recall is a subtle point reviewers will notice. The table already documents those view-control numbers, so the figure should make the interpretation explicit rather than visually bury it. 

**Fig. 6: Model card.** Fix the zero pulses/CRF bug immediately. This should be one of the strongest paper figures because it explains the synthetic assumptions. Right now it undermines Table I.

**Fig. 7: Range-Doppler diagnostics.** Use shared normalization and consider choosing examples from evidence rather than hard-coded `sg_00016` and `sg_00000`. Hard-coded examples are acceptable for reproducibility, but better choices would be: highest-scoring true positive, hardest false negative or near-miss positive, and the single false positive family. The current panels look visually random and do not make the target/confuser difference obvious enough for a radar reviewer.

**Fig. 8: KTH anchor.** Make it column-native or promote it to a two-column figure. It is currently too small to read and therefore does not earn its space.
