I reviewed the uploaded paper PDF and the live `paper/` repo lane. The current paper already has the right scientific boundary, but the visual layer is not tier-1 yet: the figures are carrying too much text, labels are too small, “locked/selected” naming is inconsistent with the Engineered Intelligence framing, and Fig. 4 is actively misleading because the red horizontal recall markers are drawn over the AP bars. The repo’s current paper lane is `detection.paper_evidence_major_upgrade_v1 → paper/generate_figures.py --strict → paper/build.sh → paper/validate_paper.py`, and `paper/generate_figures.py` delegates to `paper/generate_figures_major_upgrade_v2.py`, so nearly all figure fixes should be made in `paper/generate_figures_major_upgrade_v2.py`, not the older helper functions in `generate_figures.py`. ([GitHub][1]) 

The strongest path is: rename the method everywhere to **engineered-intelligence (EI) candidate**, preserve “selection lock” only as the audit artifact/process, replace the confusing Fig. 4 line overlay with separate bars/markers, split the KTH anchor from the algorithm workflow, add strict visual QA, and add appendix material generated from the evidence lane rather than hand-maintained claims. The paper directory already contains `echoforge_ieee.tex`, both figure generators, `validate_paper.py`, and `validate_visuals.py`, so the edits below are targeted to the existing lane. ([GitHub][2])

## 1. Main paper diagnosis

### Critical naming problem

The PDF still repeatedly uses **“locked candidate”** and **“selected”** in the abstract, figures, captions, tables, and body. For example, Fig. 3 uses “Locked candidate” and “selected” labels, and Fig. 5 is titled around “Locked candidate components.”  

Use this rule:

| Old wording                        | New wording                                                      |
| ---------------------------------- | ---------------------------------------------------------------- |
| locked candidate                   | engineered-intelligence (EI) candidate                           |
| locked advanced candidate          | EI candidate                                                     |
| selected candidate                 | EI candidate                                                     |
| selected AP                        | EI AP                                                            |
| selected lock                      | EI selection lock                                                |
| full locked candidate              | full EI candidate                                                |
| selected/selected curve in figures | EI / EI curve                                                    |
| locked algorithm figure name       | reserve for actual workflow; KTH anchor must be `anchor_overlay` |

The term **“selection lock”** can remain only when referring to the locked audit artifact and thresholding procedure.

### Fig. 4 specific issue

The “strange lines” above the selected AP bars in Fig. 4 are not rendering artifacts. They are intentionally plotted red horizontal markers for `selected_recall` inside the AP bar chart. That makes the phase chart look like it has unexplained error bars or broken annotations. The relevant code in `figure_phase_kpi()` plots selected AP bars and then overlays red horizontal line segments for selected fixed-FPR recall. 

Fix: make **EI AP** and **EI Recall@≤1%FPR** separate visual encodings. Do **not** overlay recall as unlabeled red ticks above AP bars.

### Claim strength

The abstract is close, but the claims should be stronger in structure and weaker in overreach. It correctly says the corpus is synthetic, single-seed, and not measured truth, but it should lead with what is novel and remove the old “locked candidate” wording. The result should be framed as: **EI improves low-FPR behavior and AP under a strict synthetic public-proxy benchmark; ROC AUC is lower than prior fusion; measured-platform claims are prohibited.** The current paper already acknowledges the 4,500-record blind holdout, only 24 positives from 8 groups, and lower ROC AUC versus prior fusion, which is important to keep. 

### Figure-by-figure verdict

| Figure                     | Current issue                                                                     | Required fix                                                                                                           |
| -------------------------- | --------------------------------------------------------------------------------- | ---------------------------------------------------------------------------------------------------------------------- |
| Fig. 1 signal chain        | Mostly good, but small labels and inconsistent color semantics.                   | Keep as full-width, use style helpers, consistent EI palette, larger box text.                                         |
| Fig. 2 balance/leakage     | Extremely dense; small labels; title overlap in PDF; leakage boxes unreadable.    | Rebuild as 2×3 count grid plus a full-width “leakage checks” strip; larger labels; no tiny side panels.                |
| Fig. 3 KPI                 | Too many diagnostics in one page; “selected” label; calibration x labels overlap. | Rename EI; use colormap for AP ranking; simplify calibration to nonzero bins or horizontal labels; keep KPI dominant.  |
| Fig. 4 phase/false alarms  | Red recall lines over AP bars; “selected” wording; family colors inconsistent.    | Replace with grouped bars for prior AP / EI AP / EI fixed-FPR recall; use colormap for false-alarm burden.             |
| Fig. 5 components/controls | Cramped labels; “locked” wording; deltas use blunt red/green.                     | EI title; wrap labels; use night red-green diverging colormap; annotate positive/negative deltas.                      |
| Fig. 6 radar card          | Table fonts too small; receiver impairments only partially visible; cards packed. | Split table/card areas; show all receiver impairments; bigger font; consistent box style.                              |
| Fig. 7 range-Doppler       | Pretty good but labels/colorbar squeeze the grid; row labels are too raw.         | Use explicit colorbar axis, row cards, shared scale note; keep heatmap raster.                                         |
| Fig. 8 KTH anchor          | File is named `locked_algorithm` but it is not an algorithm; y labels small.      | Rename to `anchor_overlay`; add a new actual `ei_workflow` figure.                                                     |

```python
def _clean_axis(ax: Any, *, xgrid: bool = False, ygrid: bool = False) -> None:
    if xgrid:
        ax.xaxis.grid(True, color=GRID, linewidth=0.7)
    if ygrid:
        ax.yaxis.grid(True, color=GRID, linewidth=0.7)
    ax.set_axisbelow(True)
    for spine in ("top", "right"):
        ax.spines[spine].set_visible(False)
    ax.spines["left"].set_color(GRID)
    ax.spines["bottom"].set_color(GRID)


def _short_label(text: Any, width: int = 22) -> str:
    return "\n".join(
        textwrap.wrap(
            str(text).replace("_", " "),
            width=width,
            break_long_words=False,
            break_on_hyphens=False,
        )
    )


def _comparison_color(value: float, vmin: float, vmax: float) -> Any:
    if not math.isfinite(value):
        return SLATE
    if vmax <= vmin:
        return NIGHT_RED_GREEN(0.5)
    return NIGHT_RED_GREEN(float(np.clip((value - vmin) / (vmax - vmin), 0.0, 1.0)))


def _bar_value_label(
    ax: Any,
    x: float,
    y: float,
    text: str,
    *,
    xpad: float = 0.01,
    color: str = MUTED,
    weight: str = "normal",
) -> None:
    ax.text(
        x + xpad,
        y,
        text,
        va="center",
        ha="left",
        fontsize=BAR_LABEL_SIZE,
        color=color,
        weight=weight,
    )


def _bottom_note(fig: Any, text: str) -> None:
    fig.text(0.015, 0.012, text, fontsize=7.0, color=MUTED, ha="left", va="bottom")
```

```python
def figure_phase_kpi(context: FigureContext) -> Path:
    filename = "phase_kpi.png"
    evaluation = _evaluation_summary(context)
    if evaluation:
        _note_source(filename, "phase metrics and false-alarm family breakdown")
    else:

        if STRICT_MODE:

    fig = plt.figure(figsize=(11.4, 5.7), constrained_layout=True)

        color=EI_COLOR,
        edgecolor="white",
        linewidth=0.8,
        label="EI AP",
    )
    bars_ei_recall = ax.bar(

        width,
        color=GOOD_GREEN,
        edgecolor="white",
        linewidth=0.8,
        hatch="///",
        label="EI Recall@≤1%FPR",

                va="bottom",
                fontsize=6.4,
                color=INK,
                rotation=0,
            )

    ax.set_xticks(x)
    ax.set_xticklabels(

    ax.set_ylabel("Holdout metric value", fontsize=AXIS_LABEL_SIZE)
    ax.set_ylim(0.0, 1.08)
    ax.set_title("Per-phase holdout diagnostics", fontsize=PANEL_TITLE_SIZE, weight="bold")
    _clean_axis(ax, ygrid=True)
    ax.legend(loc="upper left", ncol=1)

    # Right panel: false alarms and near-threshold context, with comparable burden coloring.
    fa_ax = fig.add_subplot(gs[0, 1])
    family_rows = _read_csv_rows(
        context.roots.paper_evidence_root / "false_alarm_by_method_family.csv"
    )
    method_rows = _read_csv_rows(
        context.roots.paper_evidence_root / "top_method_false_positive_frequency.csv"
    )
    if not family_rows or not method_rows:
        family_rows = _fallback_false_alarm_rows()
        method_rows = [
            {
                "method": "engineered_intelligence",
                "method_label": "engineered_intelligence",
                "rank": 1,
                "selected_threshold_fp_count": 1,
                "fp_per_1000_negatives": 0.2,
                "recall_at_leq_1pct_fpr": 0.8,
                "top_fp_family": "single_bird",

        ]

    # Normalize legacy labels here; do not mutate evidence files.
    method_rows = sorted(method_rows, key=lambda row: _safe_float(row.get("rank"), 99.0))
    selected_methods = [row.get("method", "") for row in method_rows if row.get("method")]
    method_to_summary = {row.get("method", ""): row for row in method_rows}

    method_to_family_rows: dict[str, list[dict[str, str]]] = defaultdict(list)
    for row in family_rows:
        method_to_family_rows[row.get("method", "")].append(row)

    totals = [

            _safe_float(row.get("false_alarm_count"))
            for row in method_to_family_rows.get(method, [])

        for method in selected_methods
    ]
    max_fp = max(totals + [1.0])

    y = np.arange(len(selected_methods))
    burden_colors = [_comparison_color(total, 0.0, max_fp) for total in totals]

        linewidth=0.8,

    fa_ax.scatter(

            color=MUTED,

        method_to_summary[method]["_display_label"] = display_label

    fa_ax.set_yticks(y)

        fontsize=7.0,

    fa_ax.set_xlabel("False-alarm count / near-threshold context", fontsize=AXIS_LABEL_SIZE)
    fa_ax.set_title("Cross-method false-alarm burden", fontsize=PANEL_TITLE_SIZE, weight="bold")

    fa_ax.legend(loc="lower right")

    _bottom_note(
        fig,
        "Each phase has n=8 positive holdout records from 8 positive groups; phase and family slices are diagnostic, not field-rate estimates.",
    )
    _add_fallback_banner(fig, filename)
    return _save_figure(fig, filename)
```
