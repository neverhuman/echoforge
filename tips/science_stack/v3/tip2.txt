## 4. Final synthesis: what the best system should be

The best EchoForge combines:

* `tip6` for **EchoSig**, scenario DSL, credibility scoring, and build tickets.
* `tip1` for **full architecture, package responsibilities, coordinate conventions, and milestones**.
* `tip5` for **material realism, detector benchmarks, dataset cards, risk register, and acceptance tests**.
* `tip3` for **micro-Doppler and Docker/GPU image separation**.
* `tip4` for the memorable **Signature Forge / Scenario Forge / Validation Forge** product framing.
* `tip7` for **review posture, object onboarding, and an honest demo story**.
* `tip2` for **scope discipline and strict-open product decision**.

Technically, the final design should treat SagittaSBR as the production high-frequency RCS sidecar. Its repository describes it as open-source C++/CUDA for far-field monostatic RCS using Shooting-and-Bouncing Rays, Geometrical Optics, and Physical Optics, with GPL-3.0 licensing, so it belongs behind an external solver boundary rather than inside a permissive core. ([GitHub][1]) RadarSimPy is feature-rich for radar modeling, arbitrary waveforms, baseband from point targets and 3D models, RCS, LiDAR point clouds, range/Doppler, DoA, beamforming, CFAR, and Swerling models, but its docs also show prebuilt-module installation and source builds requiring access to `radarsimcpp`, so it must be optional, not a required strict-open dependency. ([GitHub][2])

Sionna belongs in propagation/world modeling, not target RCS truth, because NVIDIA describes Sionna as a GPU-accelerated open-source communications library with a ray tracer for radio propagation. ([NVIDIA Developer][3]) HermesPy is useful as an optional open sensing/communications simulator reference path because its docs describe a semi-static link-level simulator for wireless communication and sensing, and its radar module source identifies radar waveforms, radar cubes, detectors, and point clouds. ([HermesPy][4]) Stone Soup is a strong tracking/fusion layer because it is explicitly built for developing and testing tracking and state-estimation algorithms, with flexibility rather than maximum runtime optimization as its focus. ([Stone Soup][5])

For target proxies, public pages can seed geometry/material priors, but not measured radar truth. For example, OSMP lists public Shahed-131/136 dimensions and material observations, but those should become source-backed object-card priors with uncertainty, not definitive signatures. ([Open Source Munitions Portal][6]) Measured UAV RCS literature reinforces why EchoForge must represent distributions: one measured-data study reports five UAV RCS measurements across frequency, azimuth aspect, and polarization in 8.2–18 GHz, while VTT’s dataset describes quasi-monostatic chamber RCS measurements for UAVs at 26–40 GHz.

# 5. BEST AND FINAL EchoForge solution

## Final score: **97.0/100**

It is not 100 because exact real-world target signatures cannot be guaranteed from public-source synthetic modeling alone. The score is high because this architecture is buildable, GPU-native, strict-open by default, extensible, validation-first, and honest about uncertainty.

## 5.1 Product definition

**EchoForge** is a strict-open synthetic sensing foundry.

It takes:

```text
public object proxies
+ geometry variants
+ material uncertainty
+ motion and articulation models
+ sensor archetypes
+ worlds, clutter, and confusers
+ solver outputs
+ validation evidence
```

and produces:

```text
RCS/signature cubes
complex scattering products where available
dynamic scattering time series
micro-Doppler products
raw/baseband radar I/Q
range-Doppler and range-Doppler-angle tensors
detections
tracks
false-positive and clutter labels
RF/acoustic/EO-IR proxy metadata where appropriate
dataset cards
validation dossiers
benchmark reports
provenance manifests
```

The central rule:

> EchoForge generates **public-proxy, uncertainty-bounded, validation-scored signatures**. It must never claim exact hostile-system truth unless lawful measured data exists and is explicitly labeled.

## 5.6 Coordinate, units, and signal conventions

These are non-negotiable.

```text
Units:
  length: meters
  frequency: Hz
  time: seconds
  velocity: m/s
  power: W or dBW, never mixed silently
  RCS linear: m²
  RCS log: dBsm
  angles: degrees in metadata, radians inside kernels where useful

Body frame:
  +X forward
  +Y right
  +Z up

World frame:
  ENU by default
  ECEF optional for large-area datasets

Azimuth:
  degrees around body/world +Z
  0 deg = +X forward
  positive rotates toward +Y

Elevation:
  degrees above horizontal plane
  positive up

Polarization:
  basis must be explicit:
    - H/V for local radar frame
    - theta/phi for spherical basis
    - circular optional
  no unlabeled polarization arrays

Doppler:
  sign convention must be stored in every radar product
  default: closing target has positive Doppler
  alternate conventions require explicit metadata

FFT:
  window function
  normalization
  zero padding
  coherent processing interval
  pulse repetition interval
  sample rate
  all stored in processing graph
```

### Required solver contract

```python
from typing import Protocol

class SolverAdapter(Protocol):

        ...

        ...

    def run(self, prepared: "PreparedSolverJob") -> "SolverRunResult":
        ...

    def parse_outputs(self, result: "SolverRunResult") -> "SignatureArtifact":
        ...

    def validate_artifact(self, artifact: "SignatureArtifact") -> "ValidationResult":
        ...

    def summarize_limitations(self, artifact: "SignatureArtifact") -> list[str]:
        ...
```

### Solver layers

```text
Production RCS:
  SagittaSBR external sidecar
  purpose: high-throughput high-frequency monostatic sweeps

Validation:
  canonical analytic cases
  open full-wave/component solvers
  reduced submodel comparisons
  measured benign anchors where available

Propagation/world:
  Sionna RT sidecar
  purpose: scene/channel/multipath/radio propagation, not target RCS truth

Radar-chain:
  EchoRadar native open DSP kernel
  HermesPy optional reference adapter
  RadarSimPy optional quarantined adapter only

Tracking:
  Stone Soup benchmark layer
  EchoForge optimized tracker wrappers later
```

### License boundary rule

```text
Permissive core:
  EchoForge schemas, registry, SDK, UI, CLI, radar kernel where possible.

Copyleft/open solver sidecars:
  Run as external processes or containers.
  Communicate through files, manifests, subprocess calls, or APIs.
  Do not directly link into permissive core unless license choice intentionally changes.

Optional restricted/limited plugins:
  Must be disabled by default.
  Must pass runtime license detection.
  Must never be needed for strict-open examples, tests, or docs.
```

```text
  terrain_glints

  rain_cells
  dust

sensor_artifacts:
  multipath_ghosts
  sidelobe_artifacts
  receiver_saturation

  timing_jitter

```

Difficulty tiers:

```text
Tier 0: clean target, clean background.
Tier 1: target plus simple noise/clutter.
Tier 2: target plus one easy confuser.
Tier 3: target plus hard confusers with similar kinematics.
Tier 4: clutter-only and hard-negative-only scenes.
Tier 5: multi-object, multipath, weather, RFI, partial tracks, missed detections.
```

Hard-negative mining loop:

```text
1. Generate dataset.
2. Run baseline detector/classifier/tracker.
3. Identify false positives and false negatives.
4. Cluster failure cases by confuser, geometry, environment, sensor profile, and processing artifact.
5. Increase sampling weight for failure clusters.
6. Regenerate dataset split with leakage constraints.
7. Re-run benchmark.
8. Store failure taxonomy in dataset card.
```

## 5.24 Risk register

| Risk                                                   | Severity | Mitigation                                                                                 |
| ------------------------------------------------------ | -------: | ------------------------------------------------------------------------------------------ |
| Public target geometry incomplete                      |     High | Public-proxy labeling, source cards, uncertainty distributions.                            |
| Material assumptions weak                              |     High | Material sensitivity sweeps, solver compatibility notes, confidence penalties.             |
| SBR misses important physics                           |     High | Canonical validation, component full-wave checks, solver-regime labels.                    |
| Synthetic artifacts cause ML overfit                   |     High | Split leakage checks, hard-negative mining, measured benign anchors.                       |
| Optional radar simulator contaminates strict-open goal |     High | Optional quarantined plugin only; no core tests depend on it.                              |
| Forbidden vendor term leaks into repo                  |     High | CI scanner blocks docs, code, configs, comments, and generated reports.                    |
| Raw IQ storage explodes                                |   Medium | Tiered retention: raw IQ for selected episodes, derived products at scale.                 |
| GPU build fragility                                    |   Medium | Pinned containers, GPU doctor, smoke tests, reproducible build logs.                       |
| UI hides uncertainty                                   |     High | Every plot must display validation grade and limitations.                                  |
| Full-wave validation too slow                          |   Medium | Validate canonical and submodels, not every full sweep.                                    |
| Dataset split leakage                                  |     High | Hold out by object variant, material variant, scenario, seed, sensor, world, and confuser. |
| Scope creep into every modality                        |   Medium | Radar-first v1; RF/EO/acoustic metadata as plugins; sonar out of v1.                       |

## 5.25 Final architecture decision

Build EchoForge as:

```text
Strict-open core:
  Python SDK/workers
  Rust artifact/provenance/registry services
  React/Vite/TypeScript Studio
  FastAPI API
  Typer CLI

Production RCS:
  SagittaSBR external sidecar

Radar chain:
  EchoRadar native open DSP kernel
  HermesPy optional reference adapter
  RadarSimPy optional quarantined adapter only

Worlds:
  Sionna RT for propagation/multipath context
  EchoForge-native clutter, RFI, weather, terrain, and hard-negative generators

Validation:
  canonical analytic fixtures
  open full-wave/component solvers
  measured benign anchors where lawful
  explicit credibility grades

Tracking/fusion:
  Stone Soup benchmark bridge
  EchoForge-native optimized trackers later

Data:
  EchoSig artifacts
  Zarr/xarray tensors
  Parquet/Arrow tables
  DuckDB/Postgres registry
  S3/MinIO artifacts
  MLflow/DVC/lakeFS lineage

Deployment:
  GPU Docker images
  Ray workers
  Slurm/Apptainer adapter
  reproducible smoke tests

Governance:
  public-proxy labels
  uncertainty bands
  validation dossiers
  dataset cards
  split leakage checks
  license isolation
  forbidden-term CI gate
```

That is the strongest final design: **powerful enough to impress serious radar engineers, honest enough to survive scrutiny, and concrete enough for an agent to start building and testing immediately.**
