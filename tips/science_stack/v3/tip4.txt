# 4. Final technical decision

Build EchoForge as:

> **A strict-open, GPU-native, radar-first synthetic sensing foundry that converts public-proxy object assumptions, material uncertainty, mesh variants, solver outputs, clutter worlds, and sensor archetypes into reproducible radar datasets with validation tiers, hard-negative stress tests, and full provenance.**

The system should **not** be a wrapper around one solver. It should be a full pipeline:

```text
source dossier
→ object proxy card
→ geometry variants
→ material variants
→ mesh QA
→ RCS/signature campaign
→ validation and uncertainty scoring
→ radar-chain simulation
→ clutter/hard-negative worlds
→ detections/classifications
→ tracks/fusion products
→ benchmark metrics
→ dataset cards and audit bundles
```

The primary RCS production engine should be **SagittaSBR**, because its repository describes an open-source C++/CUDA far-field monostatic RCS code using Shooting-and-Bouncing Rays with GO/PO, with CUDA/HIP compilation paths, MPI angle scans, and GPL-3.0 licensing. That means it should be isolated as an external solver container/process, not silently embedded into a permissive core. ([GitHub][1])

RadarSimPy should be **optional only**. Its documentation and repository show strong radar features—transceiver modeling, arbitrary waveforms, baseband simulation from point targets and 3D models, RCS, interference, LiDAR point clouds, range/Doppler processing, DoA, beamforming, and CFAR—but the project’s docs also include license configuration and build/source considerations, while the broader RadarSimX ecosystem advertises source-code quotation for related modules. That makes it useful as a comparison plugin, not a strict-open foundation. ([GitHub][2])

Sionna RT belongs in **propagation and multipath**, not target RCS truth. NVIDIA describes Sionna as a hardware-accelerated differentiable open-source communications library whose RT module is a ray tracer for radio propagation modeling. ([NV Labs][3])

For full-wave validation, use openEMS and Palace on canonical targets and submodels. openEMS is a free/open FDTD solver for 3D full-wave EM simulation, and Palace is an open-source parallel finite-element code for full-wave 3D EM simulation in frequency or time domain. ([openEMS Documentation][4])

HermesPy and Stone Soup are good optional/adapter layers: HermesPy has radar waveform, beamformer, detector, and radar cube abstractions, while Stone Soup is designed for developing and testing tracking/state-estimation algorithms, with flexibility rather than maximum runtime optimization as its stated focus. ([HermesPy][5])

# 8. Core package responsibilities

## `echoforge-core`

Responsible for manifests, IDs, hashing, schema validation, units, coordinate frames, run contexts, artifact lineage, and deterministic random seeds.

## `echoforge-assets`

Object families, source dossiers, object cards, mesh assets, geometry variants, moving-part states, and public-proxy confidence tiers.

## `echoforge-materials`

Material cards, dielectric/loss tables, PEC upper bounds, composite-like families, frequency validity ranges, uncertainty distributions, and material sensitivity sweeps.

## `echoforge-mesh`

Mesh import, unit normalization, frame normalization, watertightness checks, normals, non-manifold edge checks, material-region tagging, moving-part separation, simplification, and convergence variants.

## `echoforge-signatures`

RCS cubes, coherent scattering matrices, phase, polarization products, micro-Doppler sequences, interpolation, uncertainty propagation, and signature cards.

## `echoforge-solvers`

Solver adapter contract, SagittaSBR adapter, full-wave validators, optional plugins, solver capability registry, solver logs, container digests, and solver QA.

## `echoforge-radar`

EchoRadar kernel: waveforms, antennas, receiver impairments, propagation hooks, IQ generation, range processing, Doppler processing, angle processing, CFAR, detectors, micro-Doppler, and radar products.

## `echoforge-worlds`

Scenario DSL, terrain, sea, weather, urban/industrial clutter, multipath profiles, hard-negative objects, confuser placement, RFI/interference, sensor artifacts, and repeatable world seeds.

## `echoforge-fusion`

Detection tables, track management, association, trackers, track metrics, multi-sensor metadata fusion, and Stone Soup adapters.

## `echoforge-datasets`

Dataset manifests, artifact export, train/val/test/stress splits, leakage checks, labels, dataset cards, model cards, release promotion, and audit bundles.

## `echoforge-validation`

Canonical EM validation, mesh convergence, cross-solver comparison, radar-chain golden tests, uncertainty checks, ML benchmark validation, confidence scoring, and HTML/Markdown/PDF-style report generation.

# 9. Naming policy

Do **not** put country names, prohibited vendor names, or proprietary system names into code IDs, filenames, configs, schemas, class names, test names, or demos.

Use generic IDs:

```text
uav.proxy.delta_low_altitude_v1
uav.proxy.pusher_prop_fixed_wing_v1
uav.proxy.jet_delta_body_v1
uav.proxy.twin_boom_tactical_v1
uav.proxy.large_fixed_wing_v1
```

The source dossier can say why a public proxy exists, but the stable code ID should remain generic.

# 11. Coordinate and physics conventions

Use explicit conventions from day one.

```text
length: meters
frequency: Hz
time: seconds; nanoseconds for integer timestamps
velocity: m/s
power: watts or dBm, field-specific
angles in configs: degrees
angles in internal math: radians
RCS: m² and dBsm
world_frame: ENU, x=east, y=north, z=up
target_body_frame: x=forward, y=right, z=up
sensor_frame: x=boresight, y=right, z=up
polarization: HH, HV, VH, VV where available
```

Every solver adapter must declare its native coordinate system and angle convention, then map into EchoForge’s canonical frames.

# 12. Target library design

The target library should be **proxy-class based**, not exact-system based.

## Initial positive proxy families

```text
uav.proxy.delta_low_altitude_v1

  Small fixed-wing, pusher-prop public-proxy UAV family.

  Jet/inlet delta-body public-proxy UAV family.

uav.proxy.twin_boom_tactical_v1
  Medium tactical twin-boom public-proxy UAV family.

uav.proxy.large_fixed_wing_v1
  Larger fixed-wing public-proxy UAV family.

uav.proxy.small_commercial_multirotor_v1
  Commercial quad/multirotor family for positives or hard negatives depending task.

uav.proxy.rc_fixed_wing_v1
  RC aircraft hard-negative / comparison family.
```

## Confidence tiers

```text
T0 Placeholder
  Rough parametric shape only.

T1 Public proxy
  Public dimensions and visible geometry; no measured signature.

T2 Mesh-valid public proxy
  Mesh QA, material assumptions, and canonical validation pass.

T3 Cross-solver spot checked
  Selected submodels or simplified bodies checked against full-wave validators.

T4 Measured-anchor calibrated
  Calibrated against lawful measured data from non-sensitive proxy objects.

T5 Measured target
  Actual measured target data is lawfully available, reviewed, and documented.
```

Most public UAV-inspired families should start at **T1–T3**, not T5.

# 14. Signature generation pipeline

```text
1. Select object family and variant
2. Load source dossier
3. Resolve geometry/material uncertainty samples
4. Import and normalize mesh
5. Run mesh QA
6. Generate mesh convergence variants
7. Assign material regions
8. Plan frequency/angle/polarization sweep
9. Run production SBR campaign
10. Store complex scattering and RCS cube
11. Run canonical validation
12. Run cross-solver submodel validation where required
13. Run uncertainty propagation
14. Generate signature card and validation report
15. Promote or block artifact based on release gate
```

## Mesh QA gates

A mesh fails until these checks pass or are explicitly waived:

```text
scale sanity

orientation/frame confirmed
normals consistent

degenerate triangle report
watertightness status
disconnected component report
material regions assigned
moving parts separated
solver compatibility checked
mesh hash recorded
source dossier linked
```

# 17. Validation ladder

```text
V0 Schema valid
  Configs, cards, manifests, and artifacts validate.

V1 Mesh valid
  Mesh passes scale, orientation, normals, material tags, and solver compatibility.

V2 Canonical physics valid
  Sphere, plate, dihedral, trihedral, cylinder, cone, simple wing plate.

V3 Solver convergence checked
  Mesh refinement, angular resolution, ray density, frequency resolution.

V4 Cross-solver spot checked
  Selected canonical/submodel comparisons against full-wave validators.

V5 Component validated
  Propeller primitive, dielectric slab, lossy shell, simple inlet, metal engine proxy.

V6 Radar-chain validated
  Range, Doppler, angle, SNR, CFAR, noise, impairment, and clutter sanity checks.

V7 Measured-anchor calibrated
  Lawful, non-sensitive measured calibration objects or public measured datasets.

V8 Review-ready
  Dataset card, validation report, SBOM, source dossier, limitations, and reproducibility bundle complete.
```

# 18. Dataset split policy

Never random-split frames. Split by object, mesh, material, scenario, environment, sensor, and seed.

```text
train:
  common object variants
  common material variants
  common hard negatives
  common worlds
  common sensor archetypes

validation:
  held-out seeds
  held-out trajectories
  held-out clutter densities
  held-out material perturbations

test:
  held-out geometry variants
  held-out false-positive families
  held-out sensor archetypes
  held-out environments
  held-out weather/interference conditions

stress:
  rare hard negatives
  sensor faults
  heavy clutter
  multipath ghosts
  low-SNR targets
  swarms/crossing tracks
  OOD object classes
```

Leakage checker rules:

```text
no identical mesh hash across train/test unless explicitly allowed
no identical scenario seed across splits
no identical trajectory template across train/test
no identical object-material-state tuple across train/test
no hard-negative family leakage in OOD stress tests
```

# 19. API and CLI

## Python SDK

```python
from echoforge import Forge

forge = Forge.open("projects/public_proxy_benchmark_v1")

target = forge.objects.get("uav.proxy.delta_low_altitude_v1").variant(
    geometry="median_public",
    material="mixed_composite_metal_uncertain",
    motion="level_flight_with_dynamic_propulsion"
)

rcs = forge.signatures.build_rcs_cube(
    object=target,
    solver="sagittasbr",
    sweep={
        "frequency_hz": {"start": 8e9, "stop": 18e9, "count": 64},
        "azimuth_deg": {"start": 0, "stop": 360, "step": 2.0},
        "elevation_deg": {"start": -20, "stop": 40, "step": 2.0},
        "polarizations": ["HH", "HV", "VH", "VV"],
    },
    validation_policy="canonical_plus_convergence",
)

scenario = forge.scenarios.create(
    name="low_altitude_proxy_with_hard_negatives",
    sensor="radar.public_ku_fixed_site_v1",
    targets=[target],
    confusers=[
        "biological.bird_flock_v1",
        "commercial_uas.small_quadcopter_v1",
        "industrial.wind_turbine_v1",
    ],
    clutter="terrain_mixed_low_altitude_v1",
    seed=1337,
)

episode = forge.radar.simulate(
    scenario=scenario,
    signatures=[rcs],
    outputs=["raw_iq", "range_doppler", "detections", "tracks"],
)

dataset = forge.datasets.build(
    name="echoforge_public_proxy_cuas_v1",
    episodes=[episode],
    split_policy="heldout_geometry_sensor_confuser",
    require_validation_tier="V6",
)
```
