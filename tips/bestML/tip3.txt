Below is my **ranked top 20** for converting raw radar into ML-ready feature sets, optimized for the kind of low-altitude, low/slow, cluttered, drone/bird/small-target problem your EchoForge work appears to be targeting.

I am ranking by: **discriminative power, robustness in clutter/low elevation, deployability, data efficiency, and usefulness as a canonical feature-store format**. No survey can honestly prove it covered every radar publication ever written, but this is a broad publication-backed synthesis of the major approaches that repeatedly show up across radar ATR, micro-Doppler, automotive radar, SAR/ISAR, clutter suppression, and track-level target classification literature.

## Executive answer

The best production answer is **not one feature**. It is a **causal, track-gated, multi-representation radar feature store**:

1. **Range–Doppler / Range–Azimuth / Range–Elevation / RAD tensors**
2. **Track-gated micro-Doppler spectrograms**
3. **CFAR/blob morphology and clutter-normalized statistics**
4. **Track-level kinematics + RCS/SNR time-series**
5. **Physics-assisted features**
6. Optional research lanes: **raw complex I/Q**, **self-supervised embeddings**, **simulation-to-real**, **polarimetric/multi-frequency**, and **multimodal fusion**

The radar ATR review literature consistently identifies **micro-Doppler spectra, HRRP, SAR, and ISAR** as core radar target-characteristic forms, while also noting that deep learning can learn features directly from radar data but remains constrained by labeled-data fidelity and generalization limits. ([MDPI][20]) For your use case, I would make **micro-Doppler + multi-view RAD tensors + track/RCS history** the nonnegotiable core.

## The canonical feature architecture I would build

For your repo, I would make the feature pipeline produce **four primary artifacts** per scenario/run:

### 1. `radar_tensor_features.parquet` or chunked tensor store

Store causal tensor windows:

```text
range_doppler_log_power[time, range, doppler]
range_azimuth_log_power[time, range, azimuth]
range_elevation_log_power[time, range, elevation]
range_azimuth_doppler_log_power[time, range, azimuth, doppler]   optional/heavy
complex_iq_real_imag[...]                                         optional/research
```

Use float16/float32 log power, with clear calibration metadata. This supports CNNs, ConvLSTMs, 3D CNNs, and Transformers. It also keeps the path open for RADDet/CARRADA-style tensor learning. ([ar5iv][22])

### 2. `micro_doppler_features.parquet`

For each track or candidate blob:

```text
track_id
window_start_time
window_end_time
range_gate
doppler_spectrogram_patch
micro_doppler_bandwidth
periodicity_score
cepstral_peak_period
rotor_flash_score
positive_negative_doppler_symmetry
spectral_entropy
ridge_count
ridge_slope_stats
```

This is the highest-value feature family for small drones because propellers/rotors create distinctive periodic signatures, while birds produce wingbeat micro-Doppler. ([Nature][21])

### 3. `blob_and_physics_features.parquet`

For each frame-level candidate:

```text
cfar_cell_count
blob_area_rd
blob_area_ra
peak_snr
mean_snr
local_clutter_ratio
doppler_centroid
doppler_spread
range_extent
azimuth_extent
elevation_extent
total_reflectivity
compactness
ridge_orientation
incidence_or_aspect_proxy
```

This is the cheap, explainable baseline that makes every deep model auditable. Physics-derived Range–Doppler features are especially valuable because they encode target speed, reflectivity, area, and geometry in an interpretable way. ([ece.nus.edu.sg][23])

### 4. `track_features.parquet`

For each track and causal time window:

```text
track_id
duration
num_detections
miss_rate
range_mean / range_rate
radial_velocity_mean / variance
speed_estimate
acceleration
turn_rate
climb_rate_or_elevation_change
rcs_mean / variance / skew
snr_mean / variance
intermittency
track_smoothness
micro_doppler_stability
class_prior_context
```

Track-level features are mandatory because many radar classes are ambiguous in a single frame. Kinematic, RCS, and track-morphology features are well-established in target-classification work. ([ResearchGate][25])

## Best model recipes

### Best overall model

Use a **multi-branch temporal model**:

```text
Branch A: RD / RA / RE tensor CNN
Branch B: micro-Doppler spectrogram CNN
Branch C: track/RCS/physics feature MLP or GBDT embedding
Fusion: temporal Transformer or ConvLSTM
Output: calibrated class probabilities + uncertainty + abstain/unknown score
```

This directly matches the evidence: tensor methods preserve radar geometry, micro-Doppler captures rotor/wing motion, and track/RCS/physics features stabilize decisions across time. ([ar5iv][22])

### Best small-data model

Use:

```text
STFT micro-Doppler descriptors
+ CFAR/blob features
+ physics/RD features
+ track/RCS features
→ CatBoost / LightGBM / Random Forest / SVM
```

This will often beat a fragile deep net when labels are limited. Micro-Doppler SVM/CNN pipelines have strong measured-data precedent, and physics features are especially useful when you need interpretability. ([MDPI][37])

### Best edge/real-time model

Use:

```text
CFAR/blob features
+ compact RD/RA chips
+ track/RCS rolling features
→ tiny CNN + GBDT ensemble
```

Do **not** start with full raw-IQ end-to-end inference on edge unless you have proven latency and calibration robustness. Deep raw-radar approaches are promising, but the literature also highlights ADC-data scarcity and radar-modeling difficulties. ([arXiv][24])

### Best research model

Use:

```text
raw complex I/Q
+ masked autoencoding / contrastive pretraining
+ supervised fine-tuning on tensor/micro-Doppler labels
+ simulation/domain-randomization stress tests
```

Self-supervised radar pretraining is worth pursuing once your feature manifests are stable, especially because labeled radar data is expensive and domain-specific. ([CVF Open Access][34])

## My recommended implementation order

**Phase 1: Canonical, shippable baseline**

Build these first:

1. RD/RA/RE tensor extraction
2. STFT micro-Doppler chips
3. CFAR/blob morphology
4. Track/RCS/SNR rolling features
5. Physics-assisted RD feature vector
6. CatBoost/LightGBM + small CNN baselines

This gives you a strong, auditable baseline before raw-IQ research.

**Phase 2: Deep radar perception**

Add:

1. Multi-view tensor CNN
2. Micro-Doppler CNN
3. Temporal fusion model
4. Calibration/uncertainty head
5. Unknown/abstain class

**Phase 3: Hard-environment robustness**

Add:

1. Clutter residual/STAP/MTI features
2. Low-angle multipath features
3. Domain adaptation and simulation augmentation
4. Self-supervised pretraining
5. Optional polarimetric/multi-frequency features if hardware supports them

## The nonnegotiable feature-store rules

For ML integrity, every feature row should include:

```text
scenario_id
sensor_id
track_id
frame_id
timestamp
feature_window_start
feature_window_end
is_causal = true
radar_config_hash
calibration_hash
processing_pipeline_hash
label_source
label_time
split_id
```

The feature window must **never look into the future** relative to the label. For radar tracks, I would use purged/embargoed validation by scenario, sensor, day, geography, and target instance so the model cannot memorize correlated tracks or simulated patterns.

---

## Final ranking judgment

The **best human approach** is:

> **Causal multi-representation radar ML: multi-view RAD/RD/RA/RE tensors + track-gated micro-Doppler + CFAR/blob physics + track/RCS history, fused with temporal ML.**

The **best single feature family** is:

> **Track-gated micro-Doppler spectrograms**, especially for drone/bird/small low-slow target discrimination.

The **best first baseline** is:

> **Physics + CFAR/blob + track/RCS features into CatBoost/LightGBM**, with micro-Doppler CNN as the first deep-learning add-on.

The **highest-upside research lane** is:

> **Raw complex I/Q + self-supervised pretraining**, but only after the curated feature stack is working and receipts prove generalization.
