## Bottom line

For your current **3,900-record** dataset, I would not start with “pure raw radar into a giant neural net.” I would build a **deterministic, human-engineered radar feature factory** first, then train multiple ML heads on top of it.

The strongest general recipe is:

**raw complex ADC/IQ → calibrated radar cube → range/Doppler/angle maps → micro-Doppler windows → point clouds/tracks → physics/statistical summaries → late-fusion ML.**

That recommendation matches the dominant radar-ML literature: modern reviews organize radar representations around **ADC signal, radar tensor/cube, point cloud, grid/BEV, and micro-Doppler signatures**, with the standard FMCW processing chain extracting range, Doppler, and angle information from the raw data cube through Fourier/beamforming-style transforms. ([arXiv][1])

Below is my ranked **Top 20**, from best to worst for a practical ML pipeline.

---

## Ranking criteria

I ranked each approach by:

1. **Information retained** from raw radar.
2. **Evidence across publications/tasks**.
3. **Robustness with limited labeled data**.
4. **Ease of deterministic implementation and debugging**.
5. **How well it supports fast ablations and receipts**.
6. **How likely it is to survive sensor/domain shift.**

For your setup, implement **#1–#7 first**, add **#8 as an ablation/future-scale path**, and keep **#20 as a mandatory sanity baseline**.

# My recommended feature architecture for your dataset

## 1. Build five feature banks

### Bank A — **Radar tensor maps**

This should be your primary feature set.

For every record, generate:

* `range_doppler_log_power`
* `range_azimuth_log_power`
* `range_elevation_log_power`, if elevation exists
* `range_doppler_azimuth`, if feasible
* `range_time`
* `doppler_time`
* `angle_time`
* temporal windows at multiple scales: short, medium, long

Use deterministic preprocessing:

* DC removal
* static clutter removal
* windowing
* range FFT
* Doppler FFT
* angle FFT or beamforming
* log compression
* per-sensor normalization
* optional target-centered crop

This is the best “no options, canonical” radar ML representation.

---

### Bank B — **Micro-Doppler / time-frequency**

For each target/range gate/ROI:

* STFT spectrogram
* CWT scalogram
* optional Superlet spectrogram
* torso/limb bandwidth
* max Doppler envelope
* cadence
* asymmetry
* entropy
* ridge persistence
* positive/negative Doppler energy ratio

Use this especially if your classes involve **humans, motion phases, gesture, gait, tool use, drone rotors, vibration, or cyclic dynamics**.

---

### Bank C — **Physics/statistical scalar features**

This is the feature bank I would use with **LightGBM/XGBoost/SVM**.

Extract per frame and per window:

* weighted mean range
* weighted mean Doppler
* weighted mean azimuth/elevation
* range spread
* Doppler spread
* angle spread
* covariance of range/Doppler/angle
* peak count
* CFAR detection count
* total reflectivity
* max reflectivity
* SNR
* map entropy
* sparsity
* ROI area
* target persistence
* Doppler expansion/contraction
* acceleration and jerk
* positive/negative Doppler energy ratio
* Doppler-angle correlation
* range-Doppler centroid drift
* scattering point count
* scattering point difference
* magnitude difference rate

The last three are directly inspired by the human/vehicle Doppler-spectrum feature paper, which used scattering-point and magnitude-difference features with SVM/decision-tree classifiers. ([MDPI][15])

---

### Bank D — **Point cloud / cluster / track features**

Generate point clouds with:

* x
* y
* z
* range
* Doppler velocity
* azimuth
* elevation
* intensity/RCS
* SNR
* timestamp
* frame id
* sensor id

Then compute:

* DBSCAN clusters
* cluster count
* cluster size
* cluster spread
* velocity spread
* track length
* track fragmentation
* track acceleration
* track smoothness
* occupancy grid
* optional voxel/pillar tensor

This bank is most valuable if your labels depend on **object extent, location, trajectory, or multi-object structure**.

---

### Bank E — **Raw ADC/IQ ablation**

Keep raw ADC/IQ, but do not make it the main model yet.

Use it for:

* learned FFT ablation
* complex CNN ablation
* self-supervised pretraining
* distillation from Bank A/B/C/D
* future foundation-model scaling

Recent raw-radar/foundation work is promising, but it is generally much more data hungry. One 2025 single-chip radar foundation-model effort collected roughly million-scale raw radar samples and multi-hour synchronized data, which is far beyond your current 3,900-record set. ([CVF Open Access][16])

---

# Best model stack

Use several model families, not one.

## Tier 1 — sanity and explainability

Train these first:

* logistic regression on Bank C
* linear SVM on Bank C
* Random Forest on Bank C
* LightGBM/XGBoost on Bank C

These tell you whether the labels are learnable from clean physical summaries.

## Tier 2 — map models

Train:

* small CNN on range-Doppler
* small CNN on micro-Doppler
* small CNN on range-azimuth
* shared CNN encoder over multiple radar maps
* late fusion of CNN embeddings + Bank C scalar features

## Tier 3 — temporal models

Train:

* TCN over frame-level features
* ConvLSTM over map sequences
* transformer over per-frame embeddings
* HMM/CRF only if your labels are phase/state transitions

## Tier 4 — geometry models

Train only if point clouds are high quality:

* PointNet-style model
* sparse voxel CNN
* graph classifier
* track-feature LightGBM

## Tier 5 — raw-data research path

Train only as an ablation:

* complex CNN on ADC
* learnable FFT layer
* CubeLearn-style model
* self-supervised encoder

---

# Final ranked recommendation for your EchoForge-style dataset

If I had to pick only **one canonical pipeline**, I would use this:

```text
raw ADC/IQ
  → calibration + DC/static clutter removal
  → range FFT
  → Doppler FFT
  → angle FFT / beamforming
  → radar tensor maps:
       RD, RA, RE, RAD, RT, DT
  → micro-Doppler windows around target/phase ROIs
  → CFAR point detections
  → scalar physics summaries
  → models:
       LightGBM on scalar features
       CNN on RD/micro-Doppler maps
       ConvLSTM/TCN on temporal windows
       late-fusion classifier
```

For the first production-quality pass, I would prioritize:

1. **Bank A: radar tensor maps**
2. **Bank B: micro-Doppler**
3. **Bank C: scalar physics features**
4. **Bank D: point cloud/track features**
5. **Bank E: raw ADC ablation only**

That gives you the best blend of **accuracy, interpretability, speed, reproducibility, and receipt-friendly validation**.
