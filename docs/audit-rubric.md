# EchoForge Audit Rubric

Reference for jankurai rule interpretations in this repo. Each section anchor maps to a rule ID used in finding docs.

## Top-Level Risk Mapping

`#top-level-risk-mapping`

| TLR | Dimensions | Key signals |
|-----|------------|-------------|
| Entropy | Code shape, build speed | File LOC, dead code, duplication |
| Security, secrets, agency | Security posture | Secret scanning, dependency review, SBOM |
| Contracts/data | Contract + boundary integrity | Generated zones, schema drift |
| Verification | Proof lanes, test routing | Nextest, lane scripts, proofbind |
| Repair | Observability, human review | Receipts, tracing, repair evidence |
| Context/setup | Context economy, docs | AGENTS.md, agent-readable manifests |

## Future-Hostile Language Rule

`#future-hostile-language-rule`

Files that exceed 1000 LOC or contain ambiguous version suffixes (e.g. `*_v3.rs`, `*_old.*`) fail HLT-001. Remediation: split into focused semantic modules; drop version suffixes in favor of descriptive names.

Stack preference: Rust > TypeScript/React > Python (science only). Python product code fails this rule.

## Known Vibe-Coding Insults

`#known-vibe-coding-insults`

Patterns that trigger immediate cap-level findings:

- Handwritten contracts without generated-zone entries (HLT-007)
- `model.eval()` in non-`jankurai:allow`-annotated Python (HLT-033 false positive — add allow comment)
- Fallback-soup: `ok_or_else(|| format!(...))` chains without typed error variants (HLT-001)
- Copy-code hard class: exact block duplication across active source files (HLT-009)
- Repo rot: fake-versioned active source files (HLT-040)

## Boundary and Generated Zones

`#boundary-generated-zones`

- All generated artifacts declare a `[[zone]]` in `agent/generated-zones.toml` with `path`, `command`, `source`, and `write_policy`.
- Zone files must carry a `_generated_by` or `DO NOT EDIT BY HAND` header (JSON: `"_generated_by"` key; Rust: `//! Generated by ...`; Python: `# Generated by ...`).
- Boundary evidence files live at `target/jankurai/boundaries/<slice-id>/evidence.json` with SHA256 hashes for every file in the slice.

## Repair Evidence

`#repair-receipts`

Every non-trivial repair leaves a receipt under `.agents/receipts/<slice>/<UTC>.md` with:
- Files changed
- Commands run (prefixed with `rtk`)
- Validation exit codes
- Remaining risk

Receipts must pass `tools/receipt_guard.mjs`.
