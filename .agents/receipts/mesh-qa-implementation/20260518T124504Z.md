## Validation Results
Gates implemented (eight, in `run_qa` order):

1. `gate_finite_vertices` — FAIL if any vertex carries NaN / +-Inf; `value` = count of bad triangles.
2. `gate_no_degenerate_triangles` — FAIL on any triangle with area <= 1e-12 m^2; reports worst area in the message.
3. `gate_consistent_winding` — WARN if <5% of triangles point inward relative to the bounding-sphere centre, FAIL above. Reports inward fraction in `value`.
4. `gate_bounded_aspect_ratio` — WARN if any triangle exceeds ratio 100; FAIL if the mean exceeds 50. `value` = mean ratio.
5. `gate_bounded_dihedral_angle` — WARN on any adjacent-pair dihedral outside [10, 170] deg (180-deg flat seams treated as expected, not a violation). `value` = violation count.
6. `gate_watertight` — WARN on any open or non-manifold edge; PASS only on a clean closed surface. Open primitives (`plate`, `dihedral`, `trihedral`) get an "expected for open primitive" note in the message.
7. `gate_bounded_volume_vs_box` — PASS if signed mesh volume (divergence-theorem) sits in [5%, 101%] of bounding-box volume; SKIPPED for open primitives.
8. `gate_max_electrical_size` — SKIPPED when `freq_hz` is None or non-positive; WARN if max-extent / wavelength > 1000.

## Notes / Risks / Follow-ups
- The packet spec assumed `sphere_mesh(1.0, 32, 64)` would pass all gates cleanly. In practice the lat/lon tessellation in `mesh.rs` produces zero-area pole-sliver triangles AND a shared pole vertex that makes pole-incident edges non-manifold (a single edge is fanned across many triangles). The packet explicitly forbids modifying `mesh.rs`, so the test instead verifies that the gates that should be invariant under tessellation (finite, winding, volume, electrical-size) all Pass, and the gates that legitimately flag the lat/lon artefacts (degenerate, watertight, aspect ratio, dihedral) are allowed to Warn or Fail without claiming a bug. This is the correct semantic: any future swap to a geodesic / icosphere generator that avoids polar collapse will tighten those tests automatically.
- `inject_nan_vertex` / `inject_degenerate_triangle` are intentionally part of the public API rather than `#[cfg(test)]` helpers; they let downstream solver-adapter test suites (e.g. `echoforge-solver-contract` smoke tests) construct deliberately-broken meshes without re-implementing the mutation. They are clearly documented as failure-injection helpers.
- Edge adjacency is computed via a quantised vertex grid (1 nm) rather than f64 equality, because the sphere / cylinder generators in `mesh.rs` produce vertices through sin / cos that are not bitwise-identical across longitude slices. The quantum is well below any realistic mesh tolerance and well above f64 ULP noise.
- Dihedral-angle gate treats a strict 180-deg seam as expected (flat plate quads share co-linear normals; the gate would otherwise flood with warnings on every plate edge). Only angles in `(0, 10) U (170, 180-eps)` raise a warn.
- Volume gate explicitly skips `plate`, `dihedral`, and `trihedral`; this is hard-coded by `primitive_id` to avoid leaking false-positives on inherently open primitives. A future per-mesh "is_closed" flag in `ParametricMesh` would let us remove that primitive-id dispatch without behaviour change.
- No external dependency added; the math is `std`-only and the (private) `quantise` / `edge_key` / `build_edge_map` helpers stay inside `mesh_qa.rs`.
- No CLI subcommand was added; the world crate exposes the QA suite as a library API per the packet's "ONLY add files to `crates/echoforge-world/src/`" boundary.
