## Why

Wave 7 shipped 8 new card schemas (radar platforms, source platforms, detectors, weather profiles, 3 multi-modal sensor archetypes, pack_v2 manifest). Until a loader exists, those schemas are inert — there is no runtime path for a radar engineer to drop a YAML card into `object-packs/<their-pack>/` and have it appear in the simulator. Wave 8 stands up that runtime path as a new crate `echoforge-packs` with strict-additive integration: nothing in `echoforge-radar` is rewired, the 576-test baseline preserved, and downstream consumers opt in by depending on the new crate.

A radar engineer can now run `ef pack list`, `ef pack show <kind> <slug>`, `ef pack validate` and see the seeded packs (`public-proxy/`, `hard-negatives/`) discovered, parsed, and JSON-schema-validated against the EchoForge schema set.

## Results | Validation

- **Workspace tests**: 593 passed / 8 ignored / 68 suites (was 576 / 8 / 65 pre-Wave-8). Δ = **+17** (13 echoforge-packs unit tests across manifest+validation+discovery+registry modules + 4 integration tests over seeded packs).
- **Vendor scrub clean**: 0 matches across 260 files. No vendor names introduced in `$id` or `const` literals; loader code references vendor names only via run-time `value.get("vendor")` lookups.
- **CLI smoke**:
  - `ef pack list` → "Discovered 2 pack(s) under .../object-packs" + per-pack card breakdown.
  - `ef pack validate` → "OK: 25 card(s) across 2 pack(s) validated against 2 schema(s)" (23 hard-negatives object cards + 1 public-proxy object card + 1 material card; the validator compiles `object_card.schema.json` and `material_card.schema.json` on demand and resolves their `common.schema.json` `$ref` via the local resolver).
  - `ef pack show object_card bird-flock-dense` → name "Dense Bird Flock", tier "unvalidated", path resolves to the hard-negatives YAML.
- **Schema resolver works**: `https://echoforge.local/schemas/<name>.schema.json` `$ref` URLs that the EchoForge schemas use are intercepted by `LocalSchemaResolver` and read from `<repo>/schemas/` — no HTTP fetching, no offline-mode breakage.
- **Manifest version auto-detection**: V1Legacy reader correctly parses the seeded `object_pack_manifest.schema.json` v1 manifests at `object-packs/{public-proxy,hard-negatives}/pack.manifest.json`. V2Unified reader is exercised by the `manifest::tests::v2_manifest_classified` unit test.
- **Strict-open posture preserved**: every loaded card carries its declared `validation.tier` (V0–V5) and optional `validation.fidelity_class`. The registry exposes `min_tier_across_pack` so downstream consumers can refuse to emit artefacts below an evidence floor.

## Notes | Risks | Follow-ups

- **`SchemaCatalog::validate` re-compiles per `kind` on first miss, then caches**: 2 schemas were compiled for the 25-card validation pass (object_card + material_card). When Wave 10 ships `radar-platforms-v1/` with `radar_platform_card.schema.json`, the catalog will compile that schema too on first reference — bounded by the number of distinct `kind` values, not card count.
