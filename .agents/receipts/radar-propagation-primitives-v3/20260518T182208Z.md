## Why

The radar simulator currently sets the target return amplitude from a
target-SNR knob in `crates/echoforge-radar/src/sim.rs:253–255`:

```rust
let target_amp = 10f32.powf((config.target_snr_db as f32) / 20.0)
    * noise.awgn_sigma.max(1e-4)
    * profile.rcs_scalar.max(0.01) as f32;
```

That is a tuning knob, not physics. Correctness gate C10 in the v3 plan
calls for replacing it with the radar-equation link budget

```text
P_r = P_t · G_t · G_r · λ² · σ / ((4π)³ · R⁴ · L_total)
```

whose `L_total` term needs five concrete primitives:

1. a 4/3-Earth radar-horizon check so that a target below the horizon
   contributes zero return,
2. two-ray ground-reflection multipath at low grazing,
3. ITU-R P.676 atmospheric gas attenuation,
4. ITU-R P.838 rain attenuation, and
5. ITU-R P.453 refractive-index reference atmosphere (the source of the
   4/3-Earth k-factor itself).

This packet ships those five primitives as a NEW module. The
link-budget-replacement packet that follows (`rust-link-budget-snr-removal`)
imports them; lib.rs wiring is intentionally left to that downstream
packet so the parent agent can land it centrally without colliding with
the parallel writes to `lib.rs` that other tracks are making in the same
window.

## Dossier deviation — Test 1 expected altitude

The v3 plan specified that
`min_target_altitude_for_los_m(20.0, 100_000.0, 4.0/3.0)` should
return ≈ 568 m within 10 m and cited Skolnik eq. (2.42) for the
underlying formula. Tracing the algebra back to that formula:

```text
R_horizon  = sqrt(2 R_eff h_r) + sqrt(2 R_eff h_t)
=>  h_t  = (R_horizon − sqrt(2 R_eff h_r))² / (2 R_eff)
```

with `R_eff = (4/3) × 6_371_008.8 ≈ 8.495 × 10⁶ m` and `h_r = 20 m`,
`R = 100 000 m` gives `h_t ≈ 391.6 m`. The dossier's 568 m figure
corresponds to `h_r ≈ 0 m` (it is the `R²/(2 R_eff)` zero-antenna
limit), apparently a transcription error in the dossier. This
module implements the cited formula exactly; Test 1 pins the
mathematically correct value (391.6 m within 10 m) and the
docstring on that test calls out the deviation so the next agent
to read the v3 plan does not re-introduce the dossier figure.

## Two-ray phase-formula deviation — Tests 5 and 6

The v3 plan's docstring text quoted the small-angle two-ray
formula as `F = 2·sin(π·h_r·h_t/(λ·R))` and asserted the first
null appears at `h_t ≈ 200 m` and the first peak at `h_t ≈ 100 m`
for the 3 GHz / 80 km / 20 m geometry. Those two test values are
mutually inconsistent under that quoted formula (which would put
the first null at 400 m, not 200 m). The Balanis derivation cited
in the docstring shows the correct full-phase form is
`F = 2·|sin(2π·h_r·h_t/(λ·R))|`, under which the null is at 200 m
and the peak at 100 m — matching the spec's *numerical* test
values exactly. This module implements the correct
full-phase formula (the `4π` form for Δφ, which reduces to
`2·|sin(2π·…)|` when ρ = 1). The docstring of
`two_ray_propagation_factor_magnitude` carries the full Balanis
derivation so the symbolic-vs-numeric inconsistency in the v3
plan does not recur.

## Notes / Risks / Follow-ups

- **lib.rs wiring left to the parent agent.** The packet
  boundary explicitly says lib.rs must not be touched by this
  packet. The downstream `rust-link-budget-snr-removal` packet
  (or the parent agent batching multiple W-track outputs into a
  single coordinated lib.rs edit) is expected to add
  `pub mod propagation;` and the relevant `pub use propagation::{…};`
  re-exports.
- **Atmospheric model is the P.676 Annex 2 simplified form.** The
  Annex 1 line-by-line model is more accurate at frequencies near
  the 22 GHz water-vapor line and the 60 GHz O₂ complex, but the
  link-budget work this primitive supports targets the
  S/C/X/Ku/Ka radar bands (1–40 GHz) where the simplified
  approximation is within ~0.5 dB of the line-by-line result. A
  future packet that needs near-resonance accuracy should land an
  Annex 1 implementation behind a separate function name rather
  than mutating this one (the test-value contract should remain
  byte-stable for callers).
- **Rain coefficient table is six anchor frequencies.** That is
  the packet floor (≥ 4 anchors). Adding the full P.838-3 Table 1
  (30+ frequencies) is straightforward but was not done here to
  keep the diff focused; the link-budget packet can refine if its
  campaigns need sub-percent accuracy between, say, 12 GHz and
  15 GHz.
- **Refractivity primitive does not yet expose dN/dh.** The
  exponential profile's derivative is closed-form (`-N/h_0`); a
  follow-up packet that wants a per-altitude k-factor for ray-
  bending propagation models can add `dn_dh_per_km(altitude_m)`
  in this module without changing the existing API.
- **All temporary lib.rs edits reverted.** The receipt-author
  added `pub mod propagation;` to `lib.rs` briefly to run
  `cargo test -p echoforge-radar --lib propagation --locked`,
  then removed it. `git diff crates/echoforge-radar/src/lib.rs`
  shows no propagation reference in the final state.
