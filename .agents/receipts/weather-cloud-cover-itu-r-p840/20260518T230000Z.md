# Wave 14 — Full-stack weather physics + named weather profile cards

## Why

Wave 14 of the radar-expert credibility roadmap extends the propagation
chain (ITU-R P.676 gases, P.838 rain, P.453 refractivity — all landed
in Wave 1-6) with the three remaining weather primitives required by
the downstream radar / EO-IR detection chain:

- ITU-R P.840-8 cloud / fog attenuation (Rayleigh-region `K_L · LWC · L`)
- Pierson-Moskowitz 1964 fully-developed wind-sea spectrum and the
  Beaufort wind-force scale (per WMO Code Table 1100)
- MODTRAN-style band-integrated Vis / NIR / SWIR / MWIR / LWIR
  atmospheric transmission for sea-level horizontal paths

Five named `weather_profile` cards under `object-packs/weather-profiles-v1/`
exercise the schema landed in Wave 7 and seed the regime catalog the
end-to-end scenario chain consumes.

## Results | Validation

Acceptance-gate measurements (all inside the published tolerance bands):

- **Cloud loss at 35 GHz / LWC 0.5 g/m³ / 5 km / T 273 K**: model
  predicts `0.005 + ((35-20)/(35-20)) * (2.5-1.0) + 1.0 = 2.5` dB/km
  × 0.5 g/m³ × 5 km = **6.25 dB** (expected 6 dB ± 0.5 — PASS).

  0.860` rad/s (expected 0.86 rad/s ± 5 % — PASS).

## Notes | Risks | Follow-ups

- The MODTRAN-style EO/IR module ships an *empirically calibrated*
  Beer-Lambert form rather than a true line-by-line MODTRAN run; the
  per-band humidity coefficients (0.10/0.15/0.18 for SWIR/MWIR/LWIR)
  were tuned against the published MODTRAN sea-level-horizontal
  reference (Berk 2014 §3.3) at 5 km / 60 % RH and reproduce the
  reference τ within ~5 %. Follow-up: cross-link a small JSON-Lines
  test fixture under `tests/case_studies/` once the EO/IR sensor
  archetypes land and want to anchor on the same numbers.
- Pierson-Moskowitz uses the convention `U ≈ U_10` for the
  spectrum argument (true reference is the 19.5 m wind); incurs ~5 %
  low-bias on H_s — well inside the variance of the published fit.
- The five weather profile cards declare placeholder `fingerprint_sha256`
  values (`0000…0000`); the pack loader recomputes them via
  `echoforge_core::fingerprint_sha256` over the card payload at
  load time (see `crates/echoforge-packs/src/registry.rs`), so the
  on-disk placeholder is safe.
- Pre-existing warnings observed but *not* fixed (different work slot):
  `crates/echoforge-dataset/src/{campaign,monte_carlo}.rs` still
  reference the deprecated `RadarSimConfig::target_snr_db` field
  (compile warning, not a failure). Out of scope for this Wave-14
  packet — captured for the link-budget cleanup slot.
- Cross-card numerical consistency (Pierson-Moskowitz H_s / ω_peak /
  Beaufort) between the five YAML cards is validated in-card via the
  `validation.checks` block but not yet enforced by a workspace
  test; pending wave-15 test scaffold.
