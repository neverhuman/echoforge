# material-card-v2 — schema additive bump for physical-prior / solver / surrogate separation

## Files Changed

- `schemas/material_card.schema.json` — additive v2 extension. Added optional
  properties: `frequency_validity_hz` (numeric_range), `solver_compatibility`
  (map of solver-slug -> enum), `uncertainty_policy` (object with
  `sample_count_default`, `propagate_to_rcs_uncertainty`,
  `downgrade_confidence_if_unvalidated`, `epsilon_relative_sigma`,
  `epsilon_imag_relative_sigma`), `confidence_grade` (enum A-E),
  `thickness_m` (numeric_range), `layer_stackup` (array of layer descriptors
  with `name`, `thickness_m`, `epsilon_real_range`, `epsilon_imag_range`),
  `anisotropy_flag` (boolean), `loss_tangent_distribution`
  (object with `mean`, `sigma`, `samples`). Added `$comment` documenting the
  v2 extension. Existing `required` set is untouched; all new fields live
  under `properties` only.
- `crates/echoforge-core/src/models.rs` — added matching optional fields to
  the `MaterialCard` struct, each `Option<...>` and
  `#[serde(skip_serializing_if = "Option::is_none")]` so canonical JSON
  output stays byte-identical when the new fields are absent. Introduced
  three small helper structs (`MaterialUncertaintyPolicy`, `MaterialLayer`,
  `LossTangentDistribution`).
- `crates/echoforge-core/tests/common/samples.rs` — updated the canonical
  `material_card()` builder literal so the new optional fields are
  explicitly `None`. Required because the struct literal would otherwise
  fail to compile; keeps the canonical SHA-256 stable.
- `.agents/receipts/material-card-v2/20260518T122530Z.md` — this receipt.

Scope: schema-only additive bump plus minimum Rust binding wiring. No other
crate touched; no fixtures rewritten; no behaviour changes; no existing
field semantics modified. `schemas/common.schema.json` untouched.

## Notes / Risks / Follow-ups

- The schema bump is **additive only**: v1 documents (including the
  existing `tests/schemas/material_card.sample.json` and
  `object-packs/public-proxy-v1/material_card.yaml`) continue to validate
  unchanged. `schema_version` stays pinned at `1.0.0`; the contract bump
  is recorded inside the schema's `$comment` rather than as a wire-version
  bump to preserve the deterministic_id derivation for in-flight cards.
- The `schemars_drift` test only compares the `required` set, not the
  full `properties` set, so adding optional properties never trips it.
  If the project later wants drift detection on the optional surface,
  that test would need an extension — out of scope for this packet.
- The world crate's own `MaterialCard` struct
  (`crates/echoforge-world/src/lib.rs:113`) is unchanged and does not
  declare `#[serde(deny_unknown_fields)]`, so any future producer YAML
  that emits the new v2 keys will still parse there (the extra fields
  will be silently ignored by serde). If a stricter world-side parser is
  wanted, that crate would need its own additive bump — out of scope per
  packet boundary.
- `solver_compatibility` keys are intentionally free-form rather than
  enum-pinned; the values are enum-pinned so consumers can branch
  safely. New solvers can be added without a schema revision.
- `confidence_grade` is a flat A-E enum per the FUCKIT.md.done tip6
  cross-tip resolution. It is intentionally distinct from the validation
  envelope `tier` (which is evidence-tracking V0-V*); a producer may set
  `confidence_grade: C` even when `validation.tier: unvalidated`.
- Follow-ups (out of scope for this packet): (a) extend the canonical
  fixture / a new sample to exercise the v2 fields, once a downstream
  consumer needs the field paths exercised by validation; (b) wire
  `uncertainty_policy` into the Monte-Carlo runner so it actually
  consumes the sample_count_default and propagation flags; (c) teach the
  world::MaterialCard struct about the v2 fields if the YAML fixtures
  are ever migrated.
