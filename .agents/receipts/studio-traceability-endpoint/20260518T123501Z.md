## Why

The historical Critical Review §M flagged that the studio surface stops at the
schema-catalog view; given a detection ID, no API path walked the provenance
chain back to scenario seed, target object card, material card, sensor
archetype, and dataset card. This packet introduces that drill-down endpoint
so the React shell (and any other client) can resolve a `detection_id` into
the full traceability tree without parsing the campaign output by hand.

The endpoint is strictly **read-only** against the campaign output tree, never
writes, and emits the standard public-proxy limitation line in every response.
Detection IDs follow the deterministic format
`<record_id>__<model_id>__frame_<NNNN>` (e.g.
`record_000223__cfar_tracker_baseline__frame_0102`) so any consumer can
reconstruct the ID from a record + detector_events.json without negotiating
with the server.

  - `build_router` now `.merge(...)`s a typed-state `/provenance/detection/{detection_id}`
    subrouter onto the existing catalog/validation/contracts routes.
- `crates/echoforge-studio/src/traceability.rs` (new, ~520 LoC + tests)
  - `parse_detection_id` splits a `<record_id>__<model_id>__frame_<NNNN>` ID
    and returns a typed `ParsedDetectionId` or a `MalformedDetectionId` error.
  - `lookup_detection` walks the configured campaign roots in order:
    1. Read `campaign_manifest.json`, find the record by `record_id`.
    2. Read `detector_events.json` for that record; require a matching
       `(model_id, frame_index)` row (else `DetectionAbsent`).
    3. Read `truth_metadata.json` for `neutral_object_id` + `target_family`.
    4. Read `dataset_card.json` for `id` + `splits`.
    5. Best-effort read of an object-card YAML for `display_name`,
       `geometry_variant`, `object_family`; fall back to derived values when
       the object pack is not on disk (e.g. in CI fixtures).
    6. Read `runtime_report.json` (or the manifest) for `produced_at`.
  - `detection_handler` is the axum `GET /provenance/detection/{detection_id}`
    handler; errors round-trip as `404` (not-found / detection-absent / missing
    artifact), `400` (malformed id), or `500` (I/O / parse).
  - Response contract (`TraceabilityResponse`) is exactly what the FUCKIT
    packet plan documented:
    `detection_id`, `record_id`, `scenario{seed, preset}`,
    `target{object_card_id, public_proxy_id, display_name, object_family?,
    geometry_variant?}`, `material{material_card_id, material_family}`,
    `sensor{sensor_archetype_id, band_name}`,
    `dataset{dataset_card_id, splits}`, `detection{model_id, frame_index,
    time_s, confidence, threshold}`, `produced_at`, `limitation`
    (`"public-proxy traceability; not measured truth"`).
- `apps/web/src/runtime.ts`
  - Added `provenanceLinkForDetection(detectionId)` helper: a one-liner that
    returns the same-origin `/provenance/detection/<encoded>` URL so the
    React shell can wire a "View provenance" link without touching the
    generated client. URL-encodes the detection_id for safety.
- `apps/web/src/runtime.test.ts` (new)
  - Two vitest cases pinning the helper's URL shape and percent-encoding.

## Endpoint Contract

`GET /provenance/detection/{detection_id}` -> `200 OK` with:

```json
{
  "detection_id": "record_000223__cfar_tracker_baseline__frame_0102",
  "record_id": "record_000223",
  "scenario": {
    "seed": 20260518136,
    "preset": "shahed136-public-proxy-early-detection-v1"
  },
  "target": {
    "object_card_id": "ef:object_card:owa-delta-pusher-fixed-wing-public-proxy-v1:derived:1",
    "public_proxy_id": "owa-delta-pusher-fixed-wing-public-proxy-v1",
    "display_name": "Owa delta pusher fixed wing public proxy v1",
    "object_family": "owa_delta_pusher_public_proxy"
  },
  "material": {
    "material_card_id": "ef:material_card:owa-delta-pusher-fixed-wing-public-proxy-v1:derived:1",
    "material_family": "owa_delta_pusher_public_proxy_material_proxy"
  },
  "sensor": {
    "sensor_archetype_id": "x-band-proxy-airspace-v1",
    "band_name": "x_band_proxy"
  },
  "dataset": {
    "dataset_card_id": "ef:dataset_card:owa-delta-pusher-fixed-wing-public-proxy-v1:fixture:1",
    "splits": {"train": 700, "validation": 150, "test": 150}
  },
  "detection": {
    "model_id": "cfar_tracker_baseline",
    "frame_index": 102,
    "time_s": 51.0,
    "confidence": 0.81115806,
    "threshold": 0.8
  },
  "produced_at": "2026-05-18T12:20:20Z",
  "limitation": "public-proxy traceability; not measured truth"
}
```

Error cases:
- `400` `malformed_detection_id` -- ID does not match
  `<record_id>__<model_id>__frame_<NNNN>`.
- `404` `not_found` -- record absent from every configured campaign root, OR
  the record exists but no detector event fired at `(model_id, frame_index)`.
- `404` `missing_artifact` -- campaign root present but
  `dataset_card.json` (etc.) is missing.
- `500` `internal_error` -- I/O or JSON parse failure.

## Risks / Follow-ups

- The current resolver returns a "derived" object_card_id /
  material_card_id when the object-pack YAML is not on disk (the common
  case in CI fixtures and in the live campaign output, which doesn't
  carry per-record object cards yet). When the campaign pipeline starts
  pinning real card IDs per record (Critical Review §M follow-up), the
  resolver should switch to reading those from the record manifest rather
  than synthesizing them.
- `sensor_archetype_id` and `band_name` are currently constants
  (`x-band-proxy-airspace-v1`, `x_band_proxy`) because the campaign
  manifest doesn't record a sensor reference yet. When the campaign
  emits a sensor archetype reference (FUCKIT roadmap), the resolver
  should read it.
- The endpoint is currently mounted only when the studio is run with
  `ECHOFORGE_CAMPAIGN_ROOTS` set; otherwise it returns 404 for every
  detection ID. A future packet may auto-discover the most recent
  campaign output under `outputs/campaigns/` so the dev loop "just works".
