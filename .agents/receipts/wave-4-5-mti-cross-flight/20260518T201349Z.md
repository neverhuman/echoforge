## Problem (expert critique)

The Lane H Tier 2 CLIMB-OUT detector
(`crates/echoforge-radar/src/detectors/phase_tiered/tier_climb.rs::evaluate`)
required body Doppler of the target's radial velocity to exceed the
2-pulse MTI canceller notch (~30 Hz at S-band 2.9 GHz) before
publishing a detection. **Cross-flight** targets (a drone flying
roughly perpendicular to the radar LOS) have near-zero radial
velocity by geometry — their body Doppler falls inside the MTI notch
even though the target is otherwise observable. Without a
compensating branch, such targets are silently missed.

Skolnik, "Introduction to Radar Systems" 3rd ed., 2001, §3.7
documents this as the "MTI blind speeds" problem. Richards,
"Fundamentals of Radar Signal Processing" 2nd ed., 2014, §5.4 gives
the standard fix: when the geometry forces the target into the
notch, skip the MTI gate but require **stricter Kalman residual**
and **micro-Doppler confirmation** as compensating evidence.

## Files Changed

- `crates/echoforge-radar/src/detectors/phase_tiered/tier_climb.rs` — MTI cross-flight logic

### `crates/echoforge-radar/src/detectors/phase_tiered/tier_climb.rs`

1. New public constant `MTI_NOTCH_BODY_DOPPLER_HZ = 30.0` (Hz). The
   body-Doppler threshold below which a target is treated as
   cross-flight. The constant is expressed in body-Doppler Hz so it
   is independent of the carrier frequency; the existing
   `body_doppler_hz` helper maps radial speed → body Doppler at the
   configured carrier.

2. `ClimbDecision` struct gains two fields:
   - `cross_flight: bool` — `true` when the cross-flight branch ran.
   - `micro_doppler_confirmed: bool` — `true` when the cross-flight
     branch confirmed a propeller blade-pass line in
     [150, 220] Hz ± 15% (matches the Tier 3 piston blade-pass spec
     `tier_cruise::check_blade_pass_line`).

3. `ClimbTierConfig` struct gains two cross-flight tuning fields:
   - `cross_flight_kalman_speed_gate_mps: f64` (default 3.0; vs the
     radial branch's 5.0).
   - `cross_flight_mof_n_threshold: usize` (default 4; vs the radial
     branch's 3). The cross-flight branch trades the MTI gate for
     stricter kinematic consistency.

4. `ClimbOutTierDetector::evaluate` now delegates to a new
   `evaluate_with_spectrum(obs, slow_time_spectrum, spectrum_bin_hz)`
   that branches on `body_doppler_hz(v_radial) < MTI_NOTCH_BODY_DOPPLER_HZ`:
   - Radial branch (existing behaviour): kinematic gate → MTI notch
     check → 3-of-5 M-of-N with 5 m/s Kalman gate.
   - Cross-flight branch (new): 4-of-5 M-of-N with 3 m/s Kalman gate
     AND a confirmed blade-pass line in [127.5, 253] Hz. Both
     compensating-evidence channels must agree; either missing →
     `detected: false`.

5. New private helper `check_blade_pass_line_piston(spec, bin_hz)` —
   median-floor signal-vs-floor test in the piston blade-pass band,
   mirrors `tier_cruise::check_blade_pass_line` for the piston class.
   The cross-flight branch does not yet support the jet class (the
   Tier 2 CLIMB-OUT envelope is the piston-engine takeover phase).

### `crates/echoforge-radar/src/detectors/phase_tiered/mod.rs`

Re-exports `MTI_NOTCH_BODY_DOPPLER_HZ` from `tier_climb` so the
public-API surface includes the cutoff constant.

### `crates/echoforge-radar/src/lib.rs`

Adds `MTI_NOTCH_BODY_DOPPLER_HZ` to the crate-root re-export list so
the gate test in `tests/physics_correctness.rs` and downstream
callers can `use echoforge_radar::MTI_NOTCH_BODY_DOPPLER_HZ`.
