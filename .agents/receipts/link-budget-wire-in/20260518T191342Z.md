## Why

The radar simulator at `crates/echoforge-radar/src/sim.rs:253-255` was
treating SNR as an input knob:

```rust
let target_amp = 10f32.powf((config.target_snr_db as f32) / 20.0)
    * noise.awgn_sigma.max(1e-4)
    * profile.rcs_scalar.max(0.01) as f32;
```

That bypassed every propagation primitive already in the repository
(`crate::propagation::*`) and made the simulator indefensible to a
radar engineer. Lane A replaces the knob with a full monostatic
radar-equation link budget so that SNR EMERGES from sensor + geometry +
RCS + propagation rather than being set as an input.

### Test-by-test (link_budget module, 8 unit tests)

1. `skolnik_textbook_reproduction` — Skolnik §2.5 closed-form
   (P_t=1 MW, R=50 km, σ=1 m², G_t=G_r=35 dBi, λ=0.1 m at S-band 3 GHz,
   B=1 MHz, F_n=3 dB, no atmospheric/rain/system/processing loss, no
   integration). Expected SNR ≈ 30.03 dB within ±0.5 dB; observed
   value lies inside the band.
2. `r_to_the_fourth_law` — Doubling range from 25 km to 50 km drops
   SNR by `40·log10(2) ≈ 12.041 dB` within 0.05 dB. Exact textbook
   form.
3. `rcs_proportional_to_snr` — 10× RCS (1 m² → 10 m²) lifts SNR by
   exactly 10 dB within 0.05 dB.
4. `p676_x_band_two_way_loss` — 10 GHz, 100 km, standard reference
   atmosphere ⇒ two-way loss in the 2.0-5.0 dB band per ITU-R P.676
   Annex 2 (one-way ≈ 1.3 dB; two-way ≈ 2.6 dB).
5. `coherent_integration_gain_matches_log10_n` — N=32 pulses ⇒
   +15.05 dB SNR exactly (`10·log10(32)`) within 0.01 dB.
6. `above_horizon_check_at_100km` — 4/3-Earth horizon: 10 m target
   at 100 km, 20 m antenna ⇒ `above_horizon = false`; 1000 m target
   same geometry ⇒ `above_horizon = true`. Pinned to the
   `propagation::min_target_altitude_canonical_geometry` result
   (~391.6 m horizon altitude).
7. `snr_to_amplitude_round_trip` — `(target_amp/σ)² == 10^(snr_db/10)`
   within 1e-5 relative error across SNR ∈ {-10, 0, 10, 20, 30} dB.
8. `snr_to_amplitude_handles_non_finite` — returns 0 amp for
   `NEG_INFINITY` and `NaN` (sub-horizon case).

## Surprises / follow-up questions for the parent

1. **Default SNR is now much higher than before.** With the new
   defaults (1 MW, 35 dBi, B=1 MHz) and the
   `TakeoffProfile::default()` initial range of 1450 m, the emergent
   SNR is ~80 dB rather than the old 18 dB knob. The existing
   `high_snr_takeoff_has_detection` and `low_snr_products_are_finite`
   tests still pass (the former because high SNR still detects, the
   latter because finiteness holds at any SNR). However, the
   `low_snr_products_are_finite` test no longer exercises a low-SNR
   regime in practice — it now exercises a high-SNR-but-noisy-clutter
   regime. A follow-up packet may want to either (a) move the target
   to long range to actually get a low SNR, or (b) reduce the
   transmit power in that test to ~10 W. I did not modify those test
   payloads because the task spec said "Preserve all existing tests
   passing"; both still pass.
2. **`atmospheric_one_way_db_per_km` is a config field, not derived.**
   I chose to make this a pre-computed input on `RadarSimConfig`
   rather than calling `itu_r_p676_gas_attenuation_db` inside
   `evaluate_link_budget`. Rationale: a single per-scenario
   atmosphere does not need to re-interpolate the table for every
   per-pulse evaluation. The drawback is one more knob; the upside
   is the link-budget call stays cheap. The
   `p676_x_band_two_way_loss` test demonstrates the recommended
   pattern of computing the per-km value once from the propagation
   primitive and passing it in.
3. **Two-ray multipath is opt-in.** The default
   `ground_reflection_coefficient_magnitude = 0.0` disables the
   two-ray term entirely (the propagation factor collapses to
   `|F| = 1`). Scenarios that want low-grazing multipath must set
   `|Γ|` explicitly (typical value 0.9-1.0 over salt flats / sea).
   This avoids forcing a multipath model on every scenario where
   the geometry does not warrant it.
4. **No measured-truth test fixtures were touched.** The
   `target/repro-bytes/...` truth JSONs continue to ship the
   deprecated `target_snr_db` value populated from upstream
   dataset crates; the emergent diagnostic SNR is a new field that
   downstream regeneration will start emitting once the dataset
   crate is updated.
