## Why

The Wave 1–6 sweep delivered serious physics (radar equation, ITU-R propagation, K/Weibull clutter, MTI/MTD, OS-CFAR with closed-form alpha library, 3-tier phase-aware detector, micro-Doppler LRT, acoustic-radar Bayesian fusion, unified `synthesize_scene`). What it did not deliver: (a) named real radar platforms with antenna gain / PRF / dwell / scan / noise figure, (b) named real adversary platforms with full multi-axis physics, (c) pluggable detector / source / weather / multi-modal sensor architecture, (d) cloud cover, atmospheric ducting, Pierson-Moskowitz, MODTRAN.

A radar expert opening EchoForge today will read the `sensor_archetype` schema as 5 fields (band, freq, sample rate, waveform_family, sensor_name) and immediately dismiss it as toy. Wave 7 closes the schema gap.

## What landed

### 8 new schemas

1. `schemas/radar_platform_card.schema.json` — vendor, model, country, role, antenna (pattern_type, gain_dbi, beamwidth_az/el, aperture, polarization, sidelobes, panel_count), transmit (peak/avg power, PRF, PRI, pulse_width, waveform_parameters), receiver (noise_figure_db, system_temperature_k, dynamic_range, ADC bits, system_losses_db), scan (pattern enum, az/el coverage, scan_rate_rpm, revisit, dwell, max_tracks), declared_detection_envelope (per target class with citation + confidence A–E), vendor_datasheet_refs, osint_refs, vendor_marketing_claims (separated from physics priors), integration_refs, aliases.
2. `schemas/source_platform_card.schema.json` — extends object_card with platform_family / platform_role / country, geometry (wingspan, fuselage, chord), mass, warhead_mass, propulsion (12-variant type enum, engine_model_proxy, rated power, propeller {blade_count, length, chord, prop_diameter, rated/idle RPM, configuration}, jet_compressor {first_stage_blade_count, JEM tone bands}, rocket_booster {burn_time, peak G, exit velocity}), kinematic_envelope (cruise/max/min speeds, climb/descent, operational altitude bands, max altitude, endurance, range, turn rate, sustained/instantaneous G, max bank), launch_method enum (12 variants), terminal_behavior enum (10 variants), guidance, rcs_signature (aspect_table_ref OR inline bands × aspect_envelopes × frequency × polarization), micro_doppler_signature (blade-pass + rotation fundamentals, harmonics, AM depth, aspect visibility), ir_signature (LWIR/MWIR/SWIR ΔT, plume), acoustic_signature (SPL@100m, tonal, engine/blade harmonics, broadband bands, directivity), rf_emissions (silent_default, GNSS receiver, control link, telemetry, EIRP), aliases, source_refs, tags.
3. `schemas/detector_card.schema.json` — algorithm_family enum spanning 30 algorithms (ca_cfar, os_cfar, go/so/vi/tm_cfar, censored_mld_cfar, 2D CFAR, MTI/MTD, blob_RD, micro_doppler LRT/feature, phase_tiered, TBD variants, GLRT/AMF/STAP, polarimetric whitening, sidelobe canceller, trackers, n-way fusion, detector graphs, external), parameters object, default_thresholds, intended_target_classes / sensor_archetypes, expected_performance_envelope with cited Pd/Pfa, external_binary (stdio/gRPC/FFI for non-Rust detectors), graph_topology inline, citations.
4. `schemas/weather_profile.schema.json` — regime_class enum (14 named regimes), cloud_cover (oktas, type, base/top altitude, LWC, IWC), rain (rate, top altitude, polarization h/v ratio), fog (visibility, type, LWC), sea_state (Douglas, Beaufort, Hs, peak period, U10, Pierson-Moskowitz peak freq, sea-spike kurtosis), wind_vector_mps + log-law z0, refractivity_profile (N at MSL, gradient, k-factor, surface/elevated/evaporation duct), temperature/pressure/humidity, temperature inversion bands, MODTRAN-style eo_ir_transmission_bands (vis/NIR/SWIR/MWIR/LWIR per range with aerosol optical depth).
5. `schemas/eo_ir_sensor_card.schema.json` — band enum (vis/nir/swir/mwir cooled+uncooled/lwir cooled+uncooled/multispectral), detector (type enum, array format, pitch, NETD mK, well, integration time), optics (focal length + zoom range, aperture, f-number, transmission), fov_deg (h/v, ifov_mrad), frame_rate_hz, scan_pattern, stabilization, declared_target_range_envelope (per task: detect/recognize/identify per Johnson criteria), weather_dependence.
6. `schemas/acoustic_sensor_card.schema.json` — mic_count, array_geometry enum (single through volumetric_3d + distributed_network), aperture, sample_rate, bandwidth, sensitivity_dbv_per_pa, self_noise_db_a, bearing_accuracy_deg, doa_method enum (TDOA / SRP / MUSIC / DSBF / MVDR), unit_cost_usd_range, form_factor enum (smartphone_pole_mount … buried_geophone), network_topology, network_density_per_km2, declared_detection_envelope, weather_dependence (wind / rain / temperature gradient).
7. `schemas/passive_rf_sensor_card.schema.json` — frequency_range, IBW, sensitivity_dbm, noise_figure, aoa_method enum (8 variants), bearing accuracy, TDOA baseline & timing accuracy, antenna, target_emission_classes enum (15 variants spanning GNSS L1 through Wi-Fi/Bluetooth), network_count, declared_detection_envelope, limitations (e.g. "cannot detect RF-silent OWA drones like Shahed-136").
8. `schemas/pack_v2.schema.json` — unified pack manifest with typed `card_refs` object mapping document-kind to file-path arrays (radar_platform_card, source_platform_card, detector_card, weather_profile, eo_ir_sensor_card, acoustic_sensor_card, passive_rf_sensor_card, object_card, material_card, sensor_archetype, echosig_manifest, mesh_manifest), `pack_dependencies` for cross-pack refs, `validation_tier` + `fidelity_class`, `superseded_by`, `source_status` for back-compat with v1 manifests.
