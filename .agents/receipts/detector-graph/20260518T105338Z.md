## Notes
- Backward-compat: `crate::cfar` retained as-is; `ca_cfar_1d`, `ca_cfar_scale`, `CfarDecision`, `CfarParams` are still re-exported from the crate root. The new `CaCfarDetector` is a thin Detector-trait wrapper over the existing free function, so old call sites (e.g. `tests/radar_chain/tests/runtime.rs`, `tests/radar_chain/tests/backend.rs`, `crate::chain::RadarChain`) compile unchanged.
- `DetectorGraphRuntime` chains detectors that consume `RangeDoppler`; 1-D CFAR detectors are lifted via `RangeProjectedDetector` (row-max or row-mean projector) so the heterogeneous chain in the spec works through a single runtime signature.
- OS-CFAR alpha is reused from `ca_cfar_scale(2*N_train, Pfa)`; sufficient for synthetic-test Pfa control. Production Pfa calibration is a follow-up (see Risks).
- Micro-Doppler detector encodes `(modulation_hz, sideband_spread_bins)` into the `DetectionEvent` shape: `magnitude_db` carries Hz, `doppler_bin` carries spread. Documented in `micro_doppler_feature.rs`. Revisit if a richer event payload is needed.
- Integration test required guard_cells=20 to keep the matched-filter main lobe (~20 bins wide) out of CFAR training cells; rationale documented inline in the test.

## Risks / Follow-ups
- OS-CFAR threshold scaling is a deterministic approximation, not the exact Gandhi-Kassam closed form; calibrate alpha per `(N, k, Pfa)` before relying on Pfa numbers in production.
- Micro-Doppler detector currently treats a `RangeDoppler` row as a doppler-power spectrum; for true range-Doppler-time tensors, add a 3-D variant downstream.
- Pre-existing warning in `tests/radar_chain/tests/backend.rs` (unused `pulse_compress` import) was not in scope and left untouched.
