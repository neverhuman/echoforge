## Why

The mesh-parametric-generator packet landed the canonical
`echoforge-world::mesh::*_mesh` generators (sphere, plate, cylinder,
dihedral, trihedral) but they had no front door: an operator could only
exercise them through the test harness or by writing a one-off binary.
This packet adds a thin streaming endpoint on the studio HTTP server and
a React pane that visualizes each primitive as a 3D mesh. The
combination lets a reviewer eyeball the canonical shapes the validation
lane is asserting against without ever leaving the browser.

The endpoint is strictly synthesis-on-demand -- it never reads or writes
to the campaign output tree, and the mesh is rebuilt in-process per
request from the deterministic generators in `echoforge-world`.

## Endpoint Contract

`GET /api/mesh/list` -> `200 OK`:

```json
{
  "primitives": [
    {
      "primitive_id": "sphere",
      "display_name": "Sphere",
      "defaults": { "n_lat": 24, "n_lon": 48, "radius": 1.0 }
    },
    {
      "primitive_id": "plate",
      "display_name": "Plate",
      "defaults": { "height": 1.0, "n_h": 8, "n_w": 8, "width": 1.0 }
    },
    {
      "primitive_id": "cylinder",
      "display_name": "Cylinder",
      "defaults": { "length": 2.0, "n_axial": 4, "n_circ": 32, "radius": 0.5 }
    },
    {
      "primitive_id": "dihedral",
      "display_name": "Dihedral corner reflector",
      "defaults": { "n": 8, "side": 1.0 }
    },
    {
      "primitive_id": "trihedral",
      "display_name": "Trihedral corner reflector",
      "defaults": { "n": 8, "side": 1.0 }
    }
  ]
}
```

`GET /api/mesh/{primitive}?<params>` -> `200 OK` with binary STL bytes
and headers:

- `Content-Type: model/stl`
- `Cache-Control: public, max-age=300`
- `x-echoforge-primitive: <slug>`
- `x-echoforge-triangle-count: <count>`

Query parameters per primitive (all optional; each primitive ignores
parameters it does not consume):

| primitive  | params accepted                       |
|------------|---------------------------------------|
| sphere     | `radius`, `n_lat`, `n_lon`            |
| plate      | `width`, `height`, `n_w`, `n_h`       |
| cylinder   | `radius`, `length`, `n_circ`, `n_axial` |
| dihedral   | `side`, `n`                           |
| trihedral  | `side`, `n`                           |

Error cases:

- `400 invalid_parameter` -- `radius <= 0`, `n_lat < 2`, sample count
  above `MAX_SAMPLES = 256`, etc.
- `404 unknown_primitive` -- slug outside the canonical five.

## React Component Shape

`<MeshViewer />` ships a dropdown -> 3D canvas pane that owes nothing to
the catalog surface:

```
<article class="status-card mesh-viewer">
  <header>Mesh viewer  [badge: <slug>] [badge: <count> tri]</header>
  <controls>Primitive: <select>5 primitives</select></controls>
  <surface data-testid="mesh-viewer-surface">
    <Canvas>      (R3F, lazy-loaded)
      <ambientLight />
      <directionalLight /> x 2
      <mesh geometry={STLLoader.parse(bytes)} />
      <axesHelper />
      <OrbitControlsBinding />
    </Canvas>
  </surface>
  <dl>
    <dt>Primitive</dt>     <dd>{slug}</dd>
    <dt>Triangle count</dt><dd>{stats.triangleCount}</dd>
    <dt>Bounding box</dt>  <dd>{dx x dy x dz m}</dd>
    <dt>Status</dt>        <dd>{ok | loading... | error message}</dd>
  </dl>
</article>
```

State machine (`phase` discriminant):
`loading-list` -> `ready` -> `loading-mesh` -> (`mesh-loaded` | `mesh-error`),
with `list-error` as a terminal failure for the initial primitive-list
fetch. Selection changes abort any in-flight STL fetch via
`AbortController`.

## Risks / Follow-ups

- **Bundle delta.** `three` ships ~365 KB minified
  (`node_modules/three/build/three.module.min.js`); gzipped that is
  ~95 KB. `@react-three/fiber` adds another ~60-90 KB minified. To keep
  the contracts-view first-paint cheap, `MeshCanvas` uses dynamic
  `import('three')` / `import('@react-three/fiber')` so the heavy code
  is only fetched when the user clicks the Mesh tab. The initial bundle
  delta (when nobody clicks Mesh) is the few-KB MeshViewer module
  itself; the deferred chunk is ~150-180 KB gzipped. Once the
  pre-existing Node-version issue is resolved (see next bullet) we
  should land a one-line code-split test to keep three.js out of the
  main chunk going forward.
- **Web build/test cannot run in this environment.** `rtk npm run
  web:build` and `rtk npm run web:test` both fail with
  `ReferenceError: CustomEvent is not defined` / `SyntaxError: ... does
  not provide an export named 'styleText'`. This is a pre-existing
  toolchain mismatch (vite 8 + vitest 4 require Node 20.19+ / 22.12+;
  the runner has Node 18.19.1). Per the packet boundary ("do not try
  to fix unrelated issues") I have not modified the toolchain. The
  three.js + R3F deps install cleanly with `rtk npm install`; the
  generated `package-lock.json` should be regenerable on a Node 20
  runner. The TypeScript surface of `MeshViewer.tsx` /
  `MeshViewer.test.tsx` was sanity-checked with
  `node_modules/.bin/tsc --project apps/web/tsconfig.json --noEmit`;
  zero errors originate from my new files (the only `tsc` errors are
  pre-existing in `runtime.ts` / `runtime.test.ts` /
  `client.test.ts` / `vite.config.ts` / `main.tsx`, all introduced
  before this packet).
- **OrbitControls is wired via three's `examples/jsm/controls/OrbitControls.js`
  rather than `@react-three/drei`** to keep the dep surface small. If
  the studio later needs more advanced helpers (`<Grid />`,
  `<Environment />`, `<Text />`) it should pull `@react-three/drei` in
  one packet rather than reinventing them.
- **`MAX_SAMPLES = 256` cap** on every per-dimension sample count is a
  defensive ceiling -- a malicious caller could otherwise ask for
  `n_lat = 10_000`, `n_lon = 10_000` and pin the studio thread on STL
  encoding. The cap leaves plenty of headroom for the
  validation-grade meshes the lane uses (e.g. the sphere convergence
  test goes up to n_lat = 256, n_lon = 512; the latter would need a
  follow-up to lift the lon cap, but `/api/mesh/sphere` is not where
  that needs to live).
- **Server-side OrbitControls auto-disposal** is verified by code
  (`return () => controls.dispose()`), not by a vitest case --
  exercising it requires JSDOM + a fake canvas, which is more wiring
  than is justified for a non-load-bearing UX feature.
