## Motivation

Independent OpenRouter expert critique flagged that EchoForge's radar
simulator was missing **polarization agility**. Modern AESA radars
switch polarization pulse-to-pulse for clutter diversity and target
discrimination (Skolnik, *Introduction to Radar Systems* 3rd ed.,
§7.5.3 — clutter polarization decorrelation; §11.6 — target
discrimination via polarization). The `rcs.rs` module already supports
per-polarization tables; Lane H2's job is to wire pulse-by-pulse
polarization selection into the synthesis loop so detector chains and
downstream ML features see a non-trivial polarization channel.

## What was added

### New fields on `RadarSimConfig` (sim.rs)

```rust
#[serde(default)]
pub pol_tx_sequence: Option<Vec<Polarization>>,
#[serde(default)]
pub pol_rx_sequence: Option<Vec<Polarization>>,
```

Both default to `None` (back-compat). When `Some(vec)`, the sequence is
indexed modulo `pulse_count`. Length 2 enables the classic alternating
VV/HH agility. Setting tx and rx differently enables cross-polarization
measurements (HV / VH).

`RadarSimConfig` no longer derives `Copy` because `Vec` is not `Copy`;
all internal/test usages updated to `.clone()` at the (few)
dereference sites in `physics_correctness.rs`, `sim.rs::tests`, and
`monte_carlo.rs::run_episode` — net surface impact: 7 clone insertions,
zero new allocations on the back-compat hot path because both fields
are `None`.

### Helper on `RadarSimConfig`

```rust
pub fn polarization_for_pulse(&self, pulse_idx: usize) -> (Polarization, Polarization)
```

Defaults to `(Vv, Vv)` for back-compat. When `pol_rx_sequence` is
`None`, rx mirrors tx (matched / co-polar receive). Handles empty-vec
defensively to avoid divide-by-zero in the modulo.

### Synthesis loop wiring (`synthesize_scene` in sim.rs)

After computing the per-pulse amplitude
(`amp_base = target_amp * micro * scintillation`), the loop now
branches on whether either polarization sequence is configured:

- **Back-compat path** (both sequences `None`): `amp = amp_base`
  unchanged. Bit-equality with pre-Lane-H2 fixtures is preserved by
  *skipping* the multiplication entirely rather than multiplying by
  literal `1.0_f32` — float pipelines are not guaranteed to produce
  identical bits for the latter, and the byte-stability gate in
  `tests/physics_correctness.rs::c_unified_takeoff_wrapper_matches_scene_direct`
  is now confirmed (245/245 tests pass).
- **Polarization-agility path** (either sequence `Some`):
  `amp = amp_base * polarization_amplitude_scale(tx, rx)` where
  `polarization_amplitude_scale` is the first-order proxy below.

### First-order polarization-amplitude proxy

`polarization_amplitude_scale(tx, rx)` returns the linear amplitude
multiplier per `(tx, rx)` pair, keyed on Shahed-class / fixed-wing
nose-on observations from the open literature:

| Pair        | Linear amp     | dB     | Citation                                                                       |
| ----------- | -------------- | ------ | ------------------------------------------------------------------------------ |
| (VV, VV)    | 1.0            | 0      | Baseline (the seeded tabulated value).                                         |
| (HH, HH)    | 1.122          | +1 dB  | Skolnik 3rd ed. table 2.1; Knott/Shaeffer/Tuley, *Radar Cross Section* ch. 14. |
| (HV / VH any) | 0.316         | -10 dB | Ulaby & Long, *Microwave Radar and Radiometric Remote Sensing*, 2014, §10.2.   |
| Other       | 1.0            | 0      | Defensive fallback (Co/Cross/L/R variants not yet keyed).                      |

Documented in-code as a "first-order polarization scaling pending full
per-pulse `Rcs::evaluate(class, aspect, elev, freq, pol_tx, pol_rx, …)`
lookup integration in Lane I follow-up". The point of Lane H2 is the
**plumbing**, not the table values; Lane I follow-up swaps the proxy
for the full `Rcs` lookup without changing the surface.

## Tests added

### `sim.rs::tests` module — 3 new tests

1. `polarization_default_is_vv_back_compat` — `RadarSimConfig::default()`
   has no sequences, and `polarization_for_pulse(*)` returns `(Vv, Vv)`
   for every pulse index from 0 to `usize::MAX / 2`.
2. `polarization_sequence_alternates_vv_hh` — with
   `pol_tx_sequence = Some(vec![Vv, Hh])`, pulses 0/2/4/… resolve to
   `Vv` and pulses 1/3/5/… to `Hh`. Also covers the cross-pol
   `(Hh, Vv)` separate-sequence case and the empty-sequence defensive
   fallback.
3. `polarization_vv_vs_hh_changes_target_amp` — synthesizes an episode
   with VV-only vs HH-only sequences (stochastic noise zeroed), asserts
   the integrated-profile peak ratio is ≥ 0.5 dB and that HH > VV per
   the +1 dB scaling.

### `tests/physics_correctness.rs` — 1 new gate

`w45_h2_polarization_agility_changes_target_amp` — same construction as
test (3) above, framed as the formal H2 acceptance gate. Asserts the
integrated peak ratio is ≥ 0.5 dB and prints the measured ratio for the
receipt.

## Measured ΔSNR — VV vs HH

Pulled from `w45_h2_polarization_agility_changes_target_amp`
(`cargo test -p echoforge-radar w45_h2 -- --nocapture`):

```
[wave-4.5-H2] peak_vv = 3176.624023, peak_hh = 3564.230957,
              ratio_db = +1.000 dB (expected ≈ +1.000 dB)
```

Measured ΔSNR = **+1.000 dB** (HH-only over VV-only integrated peak).
Matches the first-order proxy exactly: `20·log10(1.122) ≈ 1.000 dB`.
The integrated range profile is a mean of per-pulse magnitudes which
scales linearly with `target_amp`, so the peak ratio recovers the
amplitude scale directly.

## Out of scope (Lane I follow-up)

- Per-pulse `Rcs::evaluate(class, aspect, elev, freq, pol_tx, pol_rx, …)`
  dispatch — swap the first-order proxy for the full lookup.
- Polarization-keyed clutter modulation (clutter cross-pol is
  ~5–10 dB lower than co-pol for rough terrain; see Ward/Tough/Watts
  §3.4). Today the clutter cube is polarization-agnostic.
- TargetClass-keyed amplitude tables (the proxy assumes fixed-wing
  nose-on; helicopters, vehicles, birds have markedly different
  polarization signatures).

## Posture

Strict-open: no measured-truth claims, no platform-specific signature
claims, no vendor-equivalent performance claims. The HH/VV scaling
values are textbook approximations cited to open-literature radar
engineering references; the *plumbing* is the deliverable, and the
table values will be superseded by the full per-pulse `Rcs::evaluate`
dispatch in Lane I follow-up.
