# Banlist Activation Receipt

- Timestamp: `20260518T113726Z`
- Packet: `banlist-activation` (per `FUCKIT.md` roadmap, 2026-05-18 critical review)
- Scope: `agent/banned-terms.toml`, `tools/vendor_scrub.mjs`, `tools/banlist_audit.mjs` (new), `Justfile`, `agent/proof-lanes.toml`, `.github/workflows/jankurai.yml`

## Why

`agent/banned-terms.toml` shipped with two `__PLACEHOLDER_*` rows and
`fail_when_banlist_empty = true`. Vendor-scrub was therefore red on
every run, gating CI on a follow-up that needed user-supplied vendor
strings.

This packet activates the **wave-1 claim-guardrail set** (tip3 §3) so
vendor-scrub can stop failing closed *without* needing user-supplied
vendor designators yet. Real vendor / platform names remain a separate
follow-up (wave 2) that needs the curator's explicit go-ahead.

## What was banned (17 entries)

All phrases verified zero-hit in tracked, non-excluded files before
adoption. Grouped by category:

- **Signature / truth overclaims (8)**: `exact real platform signature`,
  `exact target truth`, `exact signature truth`, `exact RCS truth`,
  `exact platform truth`, `true target signature`, `ground truth
  signature`, `validated against real platform`.
- **Performance / readiness overclaims (4)**: `guaranteed detection
  range`, `100% accurate signature`, `operationally validated`,
  `production-grade signature`.
- **Vendor / proprietary-equivalence overclaims (1)**:
  `platform-equivalent`. (`proprietary-equivalent` deliberately NOT
  banned — appears in negation throughout the codebase.)
- **Evasion / defeat language (4)**: `guaranteed defeat`, `guaranteed
  kill`, `defeat radar`, `evade detection`.

## Files Changed

- `agent/banned-terms.toml`
  - Removed both `__PLACEHOLDER_*` rows.
  - Added 17 real claim-guardrail rows with category headers, each row
    has `pattern` + `reason` + `case_sensitive = false`.
  - Expanded the header comment to document the authoring rules and
    the wave-1 / wave-2 split.
  - Reserved a wave-2 stub for vendor / platform designators (empty
    until a curator adds them with user authorization).
- `tools/vendor_scrub.mjs`
  - Fixed the minimal TOML parser to handle multi-line
    `key = [\n  "a",\n  "b",\n]` arrays. Previously these parsed as
    empty `[]`, so `[compliance.exclude].paths` was effectively
    inert; the file was scanning itself and every excluded path. The
    fix is a small `pendingArray` collector + a shared `applyKey`
    helper.
- `tools/banlist_audit.mjs` (new)
  - Stand-alone audit that asserts: zero placeholder rows, ≥10 real
    terms, every real term has `pattern` + `reason`, exclude paths is
    non-empty, must include `"agent/banned-terms.toml"` and `"tips/"`.
    Exits 0 / 1 / 2. Locks in this packet so the banlist cannot
    silently regress.
- `Justfile`
  - `vendor-scrub` recipe now runs `banlist_audit` first, then the
    vendor scrub itself.
  - New top-level `banlist-audit` recipe for fast standalone runs.
- `agent/proof-lanes.toml`
  - New `banlist-audit` lane entry alongside the existing
    `vendor-scrub` lane.
- `.github/workflows/jankurai.yml`
  - `vendor-scrub` job runs `banlist_audit` before the scrub itself,
    both blocking (`continue-on-error: false`).
