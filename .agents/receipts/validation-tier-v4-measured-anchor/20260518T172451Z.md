## Why

`docs/validation-tiers.md` pinned V4 as "(reserved)" while V0–V3 had
working promotion gates and V5 was reserved for lawful-measured-
validated work. With the user enabling **local-only calibration ingest**
(20260518T16xxxxZ answer to the "Keep strict-open public-proxy framing?"
question), V4 is the natural evidence tier for "method calibrated /
anchored against lawful measured data, but not fully validated". This
packet ships the gate logic so the calibration anchors produced by the
correctness-first plan (Lane J in `FUCKIT.md` 20260518T172000Z) have a
documented promotion gate to land against, rather than floating as
diagnostics.

Per the FUCKIT.md.done cross-tip resolution that separates method-
ceiling (fidelity F0–F5) from evidence-tier (validation V0–V5), the V4
gate is purely an evidence-tier evaluator and does NOT interact with
the `fidelity_class` axis. The V0/V1/V2 gate in `report.rs` and the V3
gate in `tier_v3.rs` are both left untouched — V4 is additive, mirroring
the additive pattern established by `validation-tier-v3` and
`validate-fidelity-rollup`.

## Notes

- `V4GateReport.tier` is `&'static str` (matching `V3GateReport.tier`).
  This is a producer-only struct for downstream consumers to read as
  JSON; the round-trip test deliberately checks `serde_json::Value`
  shape rather than `Deserialize<V4GateReport>` because borrowing a
  `&'static str` back from owned JSON requires either leaking the
  string or changing the field to `String` — and the V3 idiom is fine
  as-is.
- The Wasserstein-1 implementation uses a merged-quantile sweep
  (single `O(n + m)` pass over already-sorted samples plus an `O(n log n)`
  sort step inside `compute_distance`). For the typical V4 use case
  (10–1000 samples per anchor, < 20 anchors) this is well under a
  millisecond per gate evaluation.
- The KS implementation tracks running ECDF values as integer counts
  divided by sample size, taking the supremum absolute difference. The
  reference Massey (1951) test definition.
