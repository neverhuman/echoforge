## Why

`crates/echoforge-radar/src/sim.rs` currently uses
`TakeoffProfile::rcs_scalar: f64` — one number per target. Outside
reviewers (`tips/not_real/tip{1..9}.txt`) converge that this is
physically wrong:

- Real radar cross section varies by 20+ dB with aspect angle.
- It depends on frequency, polarization, and elevation.
- It fluctuates pulse-to-pulse / scan-to-scan per the Swerling models.

A scalar means the same target always looks the same. That **is** a
label leak: any detector trained on data with a constant RCS per class
will learn to read the label off the signal level, not off any
discriminating feature an operational radar would actually see.

This packet introduces the `Rcs` type and an evaluator that returns
dBsm as a function of `(target_class, aspect, elevation, frequency,
polarization, seed, pulse_index)`, with a Swerling fluctuation overlay
seeded deterministically so episodes remain bit-reproducible (Lane B,
reproducibility, is not regressed).

**This packet only lands the lookup type.** Integration into the radar
chain (i.e. swapping `rcs_scalar` for a call to `Rcs::evaluate`) is
Lane A in a separate packet; the Codex Python v2 generator can mirror
the same lookup shape so the two stay in lockstep.

## Files Changed

- `crates/echoforge-radar/src/rcs.rs` (new, 948 lines including inline
  test module)
  - Public types:
    - `pub enum Polarization { Hh, Hv, Vh, Vv, Co, Cross }` —
      polarization channel tag for `RcsLookup`. `Co` and `Cross` are
      the polarization-agnostic helpers (co-pol average and
      cross-pol average).
    - `pub enum SwerlingModel { Swerling0, Swerling1, Swerling2,
      Swerling3, Swerling4 }` — fluctuation model, per Skolnik
      *Introduction to Radar Systems* 3rd ed., ch. 2.
    - `pub const SWERLING_DEFAULT_SCAN_SIZE: usize = 32` — pulses per
      scan used by the Swerling 1 / Swerling 3 scan-correlated kernels.
    - `pub struct AspectGrid { azimuth_deg, elevation_deg }` — both
      vectors stored sorted ascending; azimuth is interpreted modulo
      360 at query time.
    - `pub struct RcsLookup { target_class, frequency_ghz,
      polarization, aspect_grid, rcs_dbsm, fluctuation, citation,
      citation_url }` — one (target, frequency, polarization) table.
      `rcs_dbsm` is stored row-major over `[azimuth × elevation]`.
    - `pub struct Rcs { tables: Vec<RcsLookup> }` — container that
      owns one or more lookup tables.
  - Public functions:
    - `Rcs::empty()` — constructs an empty container.
    - `Rcs::add_table(&mut self, table: RcsLookup)` — appends a table.
    - `Rcs::evaluate_static(target_class, aspect, elevation, freq,
      pol) -> f64` — deterministic median RCS in dBsm via
      bilinear interpolation over the chosen table's
      (aspect, elevation) grid.
    - `Rcs::evaluate(target_class, aspect, elevation, freq, pol,
      seed, pulse_index) -> f64` — same lookup with a Swerling
      fluctuation overlay seeded by `(seed, pulse_index)`. Same
      arguments → same value (Lane B reproducibility preserved).
    - `Rcs::seeded_public_proxy_v1()` — returns three public-proxy
      reference tables (small fixed-wing UAS, large bird,
      quadrotor) patterned after published aggregate measurements;
      not measured equivalents; do not claim platform-specific
      signature truth.
  - `AspectGrid::is_valid()` and `RcsLookup::is_valid()`,
    `RcsLookup::expected_len()` — small helpers used in tests and
    available to downstream code that constructs tables.
  - Lookup rules (in module doc comment):
    1. Exact `target_class` match required.
    2. Frequency: closest in **log10**-frequency wins (right metric
       for radar bands that are roughly geometrically spaced).
    3. Polarization: exact match preferred; otherwise the result is
       the polarization-average of every table at the chosen
       class+frequency.
    4. Aspect wraps modulo 360.
    5. Out-of-grid elevation (or aspect outside the grid after
       wrapping) clamps to the nearest grid edge — the module does
       **not** extrapolate beyond the cited measurement region.
  - Internal `SplitMix64` deterministic RNG mirrors the one already
    present in `sim.rs`, so no new dependency is introduced. Swerling
    1/3 use the scan-index (`pulse_index / SWERLING_DEFAULT_SCAN_SIZE`)
    as the RNG seed mix; Swerling 2/4 use the pulse index directly.
  - `#[allow(clippy::too_many_arguments)]` on `Rcs::evaluate` because
    the 8-argument signature is mandated by the packet contract.

## Citations used in seeded tables (verbatim)

- **Small fixed-wing UAS at 10 GHz, VV polarization**:
  `"MDPI Drones 2023, 7(1):39 (small fixed-wing UAV RCS aggregate
  distribution)"` — citation_url:
  `https://www.mdpi.com/2504-446X/7/1/39`.
  Pattern: 12 azimuth × 3 elevation grid. Broadside (90 / 270 deg)
  bulges up to ~-10 dBsm; nose / tail dips to ~-25 dBsm; higher
  elevations attenuate by a few dB on a fixed-wing planform.
  Fluctuation: Swerling 1 (scan-to-scan correlated).
- **Single large bird at 10 GHz, HH polarization**:
  `"Rahman & Robertson, Nature Sci Rep 8:17396 (2018) — Radar
  micro-Doppler signatures of drones and birds at K-band and W-band"`
  — citation_url:
  `https://www.nature.com/articles/s41598-018-35880-9`.
  Pattern: 12 × 3 grid. Body-only return ~-30 dBsm; broadside
  wing-flash spikes to ~-15 dBsm. Fluctuation: Swerling 3
  (chi-squared 4-DOF scan-to-scan).
- **Quadrotor at 10 GHz, VV polarization**:
  `"Ezuma et al., arXiv:2102.11954 (UAV RF and RCS statistical
  recognition)"` — citation_url: `https://arxiv.org/abs/2102.11954`.
  Pattern: 12 × 3 grid. More omnidirectional than fixed-wing
  (~-20 dBsm body return, ±2 dB azimuth variation). Fluctuation:
  Swerling 2 (rotor chopping → pulse-to-pulse decorrelation).

These tables are **PROXIES** that capture the published distribution
shape; the dBsm values are illustrative aggregate-distribution
representatives, not measurements of a specific airframe.

## Notes / Risks / Follow-ups

- **Strict-open posture.** The module docstring and the seeded-builder
  docstring explicitly say: *"public-proxy reference tables based on
  published aggregate measurements; not measured equivalents; do not
  claim platform-specific signature truth."* This phrasing satisfies
  the Wave-1 banned-terms policy (no "exact real platform signature",
  "true target signature", "ground truth signature", "validated
  against real platform", etc.).
- **Naming-policy reversal (`20260518T160000Z`).** Platform names are
  allowed in default code paths, so future tables may be tagged with
  platform identifiers (e.g. `quadrotor-class-A`, `fixed-wing-uas-X`).
  The Wave-1 overclaim guards still apply: tables MUST cite a public
  source and MUST NOT assert measurement equivalence.
- **Lane A integration is deferred.** This packet does not modify
  `sim.rs` or `lib.rs`. The TODO for the next packet:
  1. Parent: add `pub mod rcs;` and a `pub use rcs::{...}` block to
     `crates/echoforge-radar/src/lib.rs`.
  2. Lane A: replace `profile.rcs_scalar` in
     `synthesize_takeoff_episode` with a call to `Rcs::evaluate`
     using the per-pulse aspect / elevation derived from the
     `TargetState`. Until that happens, the runtime amplitude is
     still computed from `rcs_scalar`, so the label-leak gate C3 is
     **logic-ready but not yet wired**.
- **Codex Python v2 generator can mirror.** The Python radar primitives
  (currently quarantined per the `python-radar-primitives-quarantine`
  packet) can adopt the same `(target_class, freq_ghz, polarization)
  → grid` lookup shape, so the two stay in lockstep when the Python
  lane is unblocked. The Swerling kernels are simple enough to mirror
  faithfully without depending on NumPy's RNG order.
- **Frequency rule documented as log-nearest.** This is the right
  metric for radar bands (L 1, S 3, X 10, Ka 35, W 94 GHz). Linear
  nearest would over-weight high-frequency tables; log-nearest is
  symmetric on the band axis. The doc comment explains this so a
  future contributor doesn't "fix" it.
- **Out-of-grid behaviour is clamp, not extrapolate.** Refusing to
  extrapolate beyond the cited measurement region keeps the validation
  posture honest: every dBsm value the module returns came from
  bilinear interpolation inside a published source's grid (or the
  nearest edge thereof), not from a model that pretends to know what
  the RCS would be 30 dB up in elevation.
- **Reproducibility (Lane B) preserved.** The Swerling overlay is
  deterministic in `(seed, pulse_index)`, and the seed-mix function
  is documented in-source. Calling `evaluate` twice with the same
  arguments returns bit-identical f64 outputs (tested:
  `determinism_same_call_same_value`).
- **Single-argument-count clippy lint suppressed.** The 8-argument
  `evaluate` signature is mandated by the packet contract;
  `#[allow(clippy::too_many_arguments)]` is the minimal scope override.
  No other clippy or rustc warnings.
- **Tests live inside `rcs.rs` as a `#[cfg(test)] mod tests`** rather
  than a separate `tests/` integration file, because the packet
  contract forbids touching `lib.rs`, and an integration test would
  need `echoforge_radar::rcs::...` to be visible — which requires
  the parent's lib.rs edit. When parent wires `pub mod rcs;`, the
  inline tests automatically participate in `rtk cargo test -p
  echoforge-radar --locked` without any further change.

## What this unblocks

- **Lane A (radar equation integration).** Swap `rcs_scalar` for
  `Rcs::evaluate` in `synthesize_takeoff_episode` and feed it the
  per-pulse aspect (computed from `TargetState.range_m`, runway
  heading, and the radar bearing) plus the elevation derived from
  `altitude_m / range_m`. Once wired, the same-class-same-signal
  label leak (gate C3) is closed end to end.
- **Lane B (reproducibility regression suite).** The
  `determinism_same_call_same_value` test plus the
  `(seed, pulse_index)` contract guarantee that any campaign re-run
  with the same seed will produce the same RCS samples down to the
  last bit; the reproducibility runner can extend its golden-output
  comparison to the radar amplitude axis.
- **Codex Python v2 generator.** The lookup shape is simple
  enough — `(target_class, freq_ghz, polarization) → grid` —
  that the Python lane can mirror it once the
  `python-radar-primitives-quarantine` packet is unblocked. The
  Swerling kernels are reproducible across languages because the
  underlying distributions are well-specified (exponential for
  Rayleigh power, chi-squared / 4 for chi-squared 4-DOF).
- **Validation tier upgrades.** Once Lane A lands, the V2 / V3
  benchmark suite can grade detectors against an aspect-varying
  RCS source, which is the first prerequisite for a credible
  Pd / Pfa curve under the V3 (benchmarked) gate in
  `docs/validation-tiers.md`.
