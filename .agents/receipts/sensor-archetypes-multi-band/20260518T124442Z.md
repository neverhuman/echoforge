## Why

The Monte-Carlo airspace library shipped with only one sensor archetype
(`x-band-public-proxy-pulse-doppler-v1`). Without low-band coverage we
cannot do credible detection-range sensitivity studies, and without
high-band coverage we cannot do credible micro-Doppler resolution
studies. Closing the L/S/C/X/Ku/Ka set is the minimum credibility bar
for a published radar archetype library.

All new archetypes keep the strict-open posture: they are declared as
public-proxy, neutrally named, with band/waveform/RF parameter ranges
drawn from public radar handbook bands. No measured-truth performance
number is asserted; every parameter is a sampling range, not a point
claim.

## Notes / Risks / Follow-ups

- **Public-proxy posture preserved**: every new archetype id contains
  `public-proxy`, every `display_name` calls itself
  "Public-Proxy ... Archetype", every parameter is a sampling range
  drawn from public radar-handbook band edges. No measured-truth
  number is asserted.
- **Schema fit**: the `sensor_archetype.schema.json` file is a
  *document* schema (with `id`/`kind`/`provenance`/`license`/`validation`
  envelopes) used for emitted archetype documents, not for the
  *config-library entries* in `airspace-objects-v1.json`. The
  config-library entries follow the `SensorArchetypeConfig` Rust
  struct, which I matched exactly.
- **Pulse-count range**: I kept `[16, 96]` for all bands. A future
  packet may want to widen Ka-band pulse counts (short PRI permits
  more pulses per CPI) but that is a tuning question, not a
  correctness question, and lives outside this packet's scope.
- **Cross-band presets only cover the `low-altitude-fixed-wing-takeoff`
  scenario** — adding L/Ka mirrors of the other four presets is a
  reasonable follow-up but was not requested here. The two added
  presets are sufficient to unblock cross-band sensitivity studies.
- **Pre-existing `echoforge-world::mesh_qa` failures**: out of scope
  for this packet. Track under a separate `mesh-qa-regression` packet
  if not already filed.
