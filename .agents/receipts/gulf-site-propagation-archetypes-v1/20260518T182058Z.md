## Why

The v3 correctness-first plan pins the three-phase low-altitude UAS
detection benchmark to a single UAE-coastal S-band surveillance archetype
with target launch sites at 50 / 100 / 150 km baseline ranges. Before
the phase timeline slicer (`phase-timeline-slices-v3`) or the unified
scene generator (`unified-scene-generator-v1`) can land, the workspace
needs **one canonical archetype** that nails down site geometry, sensor
parameters, target launch sites, and environment state — all in a
strict-open public-proxy posture with open-source citations.

This packet ships **only the scenario archetype loader and its embedded
JSON**. It does not run a campaign, compute Pd/Pfa, or interact with the
fidelity / validation tier evaluators. Subsequent packets layer
propagation, phase slicing, and scene generation on top of the loaded
`SurveillanceScenario` struct.

Per the local coordination scratchpad naming-policy reversal (`20260518T160000Z`), platform
names are allowed in default code paths but Wave-1 banned-terms posture
stays active. This archetype intentionally uses the neutral
"long-range air surveillance" framing rather than naming any specific
operational radar system, and pins
`strict_open_posture` as a stable string downstream consumers can
surface verbatim when citing this scenario.

## Notes / Risks / Follow-ups

- **`thiserror` is not a dep on this crate.** The packet spec
  declared `ScenarioLoadError` with `#[derive(thiserror::Error)]`
  and listed `thiserror` as already in `Cargo.toml`, but the
  current `crates/echoforge-dataset/Cargo.toml` only has `csv,
  echoforge-core, echoforge-radar, echoforge-sig, indicatif,
  ndarray, serde, serde_json, serde_yaml, smartcore` (+
  `sha2, tempfile` dev-deps). Per the packet boundary "do not add
  new dependencies", I mirrored the manual-impl pattern used by
  `monte_carlo::DatasetError` (manual `Display`, manual
  `std::error::Error`, manual `From<...>` impls) rather than
  silently introducing a new crate dep. The public API surface
  (`ScenarioLoadError::{Io, Json, Schema}`, `Display`,
  `std::error::Error::source`) is byte-stable to the spec.
- **`lib.rs` was temporarily modified for validation, then
  reverted byte-for-byte.** The packet states "DO NOT edit. The
  parent agent will add `pub mod scenarios;` and re-exports
  centrally." The validation gate explicitly allows "may need
  temp lib.rs wire; revert before finishing", which I did.
  `git diff crates/echoforge-dataset/src/lib.rs` shows only
  pre-existing diff from before my session (`pub mod campaign`,
  `pub mod ml_training`, etc.); no line added by this packet
  remains.
- **`Cargo.toml` is unmodified.** `git diff
  crates/echoforge-dataset/Cargo.toml` shows only the
  pre-existing diff (csv, indicatif, serde_yaml, smartcore, sha2);
  this packet added no new dependency line.
- **`local coordination scratchpad` is unmodified.** Per packet boundary.
- **Other dataset source files are byte-stable.** The packet
  added only the new `scenarios.rs` file; `benchmark.rs`,
  `campaign.rs`, `export.rs`, `leakage.rs`, `ml_training.rs`,
  `monte_carlo.rs`, `split.rs` were not touched.
- **Sensor archetype framing.** Per the packet spec instruction
  "DO NOT name those systems specifically as a model; just use
  representative values for a 'long-range air surveillance'
  archetype", `archetype_id` is
  `"s-band-public-proxy-pulse-doppler-v1"` and the `display_name`
  / `notes` describe the class rather than naming a specific

- **`embedded_uae_coastal()` panics on embedded JSON corruption.**
  This is intentional: the compile-time-embedded JSON is a
  build-asserted invariant. The `embedded_uae_coastal_parses`

  `load_round_trips_through_tempfile` test requires structural
  equality. `PartialEq` is byte-stable across the public API and
  costs nothing for downstream readers; serializers /
  deserializers are unaffected.
