# Dataset Card HTML Renderer Receipt

- Timestamp: `20260518T125528Z`
- Packet: `dataset-card-html` (FUCKIT.md packet — single-file static
  HTML view of a `dataset_card.json`)
- Owner: claude

## Scope

- Build a Node-only static-HTML renderer for `dataset_card.json`
  documents (per `schemas/dataset_card.schema.json`). Single-file
  output, inline CSS, no JS, no external assets, deterministic bytes
  across reruns. Wired through `rtk` via a new Justfile recipe.
- Renderer optionally consumes sibling artifacts: `class_balance.json`,
  `leakage_report.json`, `benchmark_report.json`. Each is opt-in and
  declared via its own flag; the renderer still produces a valid
  minimal HTML when no companions are supplied.
- Strict-open posture: the rendered HTML mirrors what the JSON
  asserts. Validation tier and overall status are echoed from
  `card.validation`; no synthesized "validated" claims. Footer
  disclaimer makes that posture explicit.
- Purely additive: no schema, Rust crate, agent config, .github file,
  or pre-existing tool was touched.

## Files Changed

- `tools/render_dataset_card.mjs` (new, Node ESM)
  - Single-file HTML5 renderer. Accepts `<dataset_card.json>` plus
    optional `--out <output.html>`, `--class-balance <p>`,
    `--leakage <p>`, `--benchmark <p>`. Default output is
    `<input>.html` next to the input.
  - Validates required dataset_card fields (`id`, `kind ==
    "dataset_card"`, `public_proxy_id`, `dataset_name`,
    `source_campaign_ids` non-empty, `provenance`, `license.spdx_id`,
    `validation.tier`, `splits.{train,validation,test}` numeric).
  - Renders sections in this order: header (dataset name, public
    proxy id, id, tier/status/uncertainty/fidelity badges); splits
    proportion bar + counts table; validation checks table; class
    balance (headline + sorted per-bucket / per-target-family /
    per-hard-negative-family bars); source campaigns list; leakage
    report (badge from findings count + policy id + checked keys);
    benchmark report (per-model TPR/FPR/mean-time-to-detect table +
    known limitations); provenance + license footer with strict-open
    disclaimer.
  - Bar charts are plain `<div>` rectangles with `width: <pct>%` and
    a label — no Plotly, no D3, no canvas, no external library.
  - All CSS lives in one inline `<style>` block. Color palette is a
    fixed 12-color array iterated by index, so the same input always
    gets the same colors.
  - Determinism: every object is iterated by sorted keys; no
    timestamps, no random, no Map/Set with undefined iteration; all
    percentages are rounded to 2 decimal places via fixed-precision
    string formatting before being interpolated.
  - Exit codes: 0 success / 1 validation-or-IO / 3 usage error.

## Validation

- The renderer is intentionally output-faithful: it never invents a
  "validated" claim, never collapses warn/fail into pass, never
  hides a finding. The leakage badge is derived purely from
  `findings.length === 0`. The validation-tier badge color is
  cosmetic (warn-amber for `basic`, pass-green for `benchmarked` /
  `measured`) but the badge text is the literal tier string from the
  JSON.
- The footer carries an explicit disclaimer: "This page renders the
  dataset_card JSON as-is. It does not assert anything beyond what
  the source document declares."
- Determinism property: test 5 hashes two outputs and asserts
  sha256-equality. If a future change adds a timestamp, randomness,
  or undefined-order iteration, this test fails before the bytes
  drift into any repro-bytes lane downstream.
- No npm dependencies installed; only Node std (`fs`, `path`,
  `crypto`, `child_process`, `os`, `url`).
- The class-balance section handles each sub-block independently
  (`bucket_counts`, `target_family_counts`,
  `hard_negative_family_counts`) — any missing block is silently
  skipped, and a completely empty class_balance file renders no
  class-balance section at all.
