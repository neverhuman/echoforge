# detector-micro-doppler-lrt-classifier receipt (Wave 6 Detector A)

## Summary

Adds a Neyman-Pearson likelihood-ratio classifier over a five-feature
micro-Doppler vector that discriminates drone vs bird vs helicopter.
Closes the "how do you discriminate drones from birds?" reviewer
question with a public-proxy reference library cited to Chen 2011,
Rahman-Robertson Nature 2018, Tahmoush 2015, and MDPI Drones 2023.

## Feature Vector Design

Five scalar features extracted from a slow-time complex range-Doppler
slice at the target's range bin:

1. `rotor_fundamental_hz` — dominant non-DC bin of the zero-padded
   slow-time DFT magnitude spectrum (Chen 2011 §3.2; Tahmoush 2015 §III).
   Spectrum-based estimator chosen over autocorrelation peak-picking
   because autocorrelation lag estimators are biased by sample-count
   effects at high lag and tend to alias onto period harmonics.
2. `modulation_depth_db` — peak-to-mean ratio of the slow-time
   magnitude spectrum, dB.
3. `harmonic_ratio` — power at 2x fundamental divided by power at
   fundamental, capped to [0, 10] (Tahmoush 2015 §III.B; Chen 2011
   Fig 3.16).
4. `spectral_entropy` — Shannon entropy (bits) of the L1-normalised
   slow-time spectrum.
5. `body_doppler_centroid_hz` — magnitude-weighted Doppler centroid,
   proxy for body radial velocity.

Classifier: independent Gaussian per-feature log-likelihoods summed
to a class log-likelihood, with softmax over equal priors. This is
the Neyman-Pearson optimum for equiprobable hypotheses under the
two-moment public-proxy envelope (Skolnik §9.5).

## AUC Numbers (100 synthetic samples per class)

Pairwise AUCs measured on Box-Muller draws from each class envelope,
seeded deterministically. The classifier compares
`log_lik(class_a) - log_lik(class_b)` against a Mann-Whitney U
threshold sweep:

| Pair                       | AUC    |
|----------------------------|--------|
| Quadcopter vs Bird (gate)  | 1.0000 |
| FixedWingUav vs Bird       | 1.0000 |
| Helicopter vs Quadcopter   | 1.0000 |
| FixedWingUav vs Quadcopter | 1.0000 |
| FixedWingUav vs Helicopter | 1.0000 |
| Helicopter vs Bird         | 1.0000 |
| 4-class aggregate accuracy | 1.0000 |

The AUCs are perfect because the public-proxy reference envelopes are
deliberately widely spaced (e.g., bird wingbeat 5 Hz vs quadcopter
400 Hz is tens of sigmas apart in the rotor-fundamental feature).
This is the *upper bound* of classifier performance on the
envelope-fit assumption; real-world AUC will be lower once measured
distributions (which include feature drift from aspect angle, snr,
and platform variation) are substituted. The 0.85 / 0.90 / 0.95
gate thresholds in `physics_correctness.rs` are calibrated to leave
headroom for that real-world degradation while still catching
classifier-implementation regressions.

## Strict-Open Posture Audit

- No measured-truth claim anywhere in the module or tests.
- Every reference envelope cites open literature; the doc comments
  carry the citation inline.
- The synthetic-sample helper is `#[cfg(test)]`-only so the runtime
  build cannot accidentally emit envelope-drawn features as if they
  were measurements.

## Risks | Follow-ups

- The four-class envelope is calibrated for X-band; K-/W-band
  detectors would want a separate library keyed by carrier. The
  classifier API accepts an arbitrary `&[ReferenceSignature]` slice,
  so a future lane can swap in a band-specific library without
  changing the LRT machinery.
- The current `extract_features` uses a naive O(N*M) DFT (8-256
  slow-time samples is fine; if it ever drives the full RDA cube it
  should switch to rustfft).
- No GPU offload — explicit per the detector-graph CPU-only contract.
