## Summary

Lane I of the Radar Expert Credibility Sweep — refactor the simulator
so all target classes (positives + confusers) traverse a single
physics path. Before this lane, the simulator carried two generators:
`synthesize_takeoff_episode` (full physics for the Shahed-class
positive) and `build_frame_products` in
`echoforge-dataset/src/ml_training.rs` (envelope statistics for
confusers). The bifurcation meant the generator identity labelled the
class — exactly the red flag a radar engineer would call out on
review. Lane I introduces a unified
`synthesize_scene(scene, config, noise, seed) -> SyntheticEpisode`
entry point. `synthesize_takeoff_episode` is now a thin back-compat
wrapper that constructs a one-entity `SceneDescriptor` (with
`TargetClass::ShahedClassPiston` + `TargetKinematics::FromTakeoffProfile`)
and forwards through the unified path. The wrapper output is
byte-stable with the pre-Lane-I implementation, so every existing
reproduction fixture and physics-correctness test passes unchanged.

## Design decisions

1. **Layered refactor (single-entity wiring first).** The unified
   `synthesize_scene` body is the byte-for-byte former body of
   `synthesize_takeoff_episode`, with the surrounding type plumbing
   replaced. Multi-entity scenes and native per-class kinematics
   (Bird, GroundVehicle, WindTurbine, …) are explicitly Lane J's
   responsibility — wiring them today, before per-class RCS-aspect
   dispatch and kinematics modules exist, would constitute a
   measured-truth claim about confuser physics that Wave 4 cannot
   honestly defend. A `debug_assert_eq!(scene.targets.len(), 1)` and
   a `panic!` on the `_UnusedFuture` kinematics variant gate the
   single-entity contract.
2. **`SceneDescriptor` fields mirror existing config / noise.** The
   `geometry` / `environment` fields restate the geometry +
   atmospheric + clutter terms that previously lived in
   `RadarSimConfig` and `NoiseProfile`. Lane I keeps the legacy
   fields as the source of truth for the physics path so byte-
   stability is provable; Lane J flips the source-of-truth to the
   scene when multi-entity dispatch lands.
3. **`TargetClass` enumerates the full confuser roster up-front.**
   The variant list (ShahedClassPiston / ShahedClassJet / Bird /
   GroundVehicle / WindTurbine / Balloon / Kite / MultipathGhost /
   TerrainGlint / Helicopter / ManRadarReturn) is fixed in Lane I so
   on-disk JSON fixtures from Lane J's dev work can be parsed by
   Lane I binaries. Only `ShahedClassPiston` is honoured by the
   physics path today; the others round-trip through serde for the
   benefit of downstream campaign-runner schemas.
4. **`TargetKinematics` carries a reserved `_UnusedFuture` variant.**
   This preserves discriminant space without breaking serialized
   fixtures when Lane J adds native kinematics. `serde(rename =
   "_unused_future")` keeps the on-disk discriminant stable.

## `scene.rs` structure

- `SceneDescriptor { geometry, environment, targets }` — the
  scene-level entry payload.
- `SiteGeometry { antenna_altitude_agl_m }` — antenna height shared
  by every entity.
- `EnvironmentDescriptor { clutter_regime, atmospheric_one_way_db_per_km,
  rain_rate_mm_per_h, ground_reflection_coefficient_magnitude }` —
  shared environment terms (clutter regime, atmospherics, multipath).
- `TargetEntity { class, kinematics, spawn_time_s }` — one per scene
  entity.
- `TargetClass` — 11-variant enum spanning positives + confusers
  (see "Design decisions" §3).
- `TargetKinematics::FromTakeoffProfile(TakeoffProfile)` — the
  migration bridge variant; `_UnusedFuture` reserves discriminant
  space for Lane J.
- Three inline tests: `scene_descriptor_roundtrip_serde`,
  `scene_descriptor_minimal`, `target_class_serde_covers_all_variants`.

## Byte-stability evidence

The unified path's byte-stability with the legacy wrapper is the
core correctness gate of Lane I. Three independent test surfaces
verify it:

1. **`tests/physics_correctness.rs::c_unified_takeoff_wrapper_matches_scene_direct`**
   — the headline gate. Runs the same `(config, profile, noise, seed)`
   tuple through both `synthesize_takeoff_episode` and a hand-built
   `SceneDescriptor` + `synthesize_scene` call, then asserts
   byte-equal IQ (per-sample `.re.to_bits()` and `.im.to_bits()`
   comparison), per-pulse range profiles, integrated range profile,
   range-Doppler magnitude proxy, complex range-Doppler grid (per-cell
   bit comparison), detections, and `diagnostic_snr_db`. This is the
   strictest possible bit-stability gate the type system allows.
2. **`tests/physics_correctness.rs::c_unified_takeoff_wrapper_matches_scene_direct_multi_scenario`**
   — three scenarios: K-distribution clutter + multi-blade Shahed
   propeller, sub-horizon target (link_budget zeros the amplitude),
   and the canonical low-pulse default. Each scenario asserts
   byte-equal integrated profile + detections through both paths.
3. **`src/sim.rs::tests::synthesize_scene_single_target_matches_legacy`**
   — the in-module sibling gate. Runs the canonical low-pulse default
   through both paths and asserts byte-equal integrated profile +
   detections.

All three pass. The pre-Lane-I test surface (192 tests) continues to
pass byte-stable, confirming the wrapper is observationally
indistinguishable from the legacy entry point. Total radar test
count: **195 passed, 7 ignored (4 suites, ~24 s)** — three new tests
relative to the pre-Lane-I baseline of 192.

## Lane J handoff note

Lane I deliberately does **not** wire native confuser kinematics or
multi-entity dispatch into `synthesize_scene`. Lane J's scope is:

1. Add native `TargetKinematics` variants for Bird (constant-velocity
   small target with bird wingbeat micro-Doppler), GroundVehicle
   (low-altitude near-ground constant-velocity), WindTurbine
   (stationary with rotor micro-Doppler), Balloon (drift kinematics
   + small RCS), Helicopter (rotor micro-Doppler with body Doppler),
   MultipathGhost (parent-target ghost geometry), TerrainGlint
   (static high-RCS bin), ManRadarReturn (stationary), Kite
   (drift), ShahedClassJet (legacy `TakeoffProfile` with jet
   propulsor).
2. Extend `synthesize_scene` to dispatch each entity through the
   appropriate per-class physics + sum into a shared IQ grid.
3. Promote `scene.geometry` / `scene.environment` to source-of-truth
   for the physics path (today they round-trip but the legacy
   config/noise fields drive the physics).
4. Remove the `debug_assert_eq!` and `_UnusedFuture` panic gates.
5. Retire `build_frame_products` in
   `echoforge-dataset/src/ml_training.rs` (the envelope-statistics
   confuser generator that Lane I left untouched) in favour of the
   unified path.

## Strict-open posture

No measured-truth claims. The wrapper produces byte-identical output
to the pre-Lane-I path; the refactor is purely type-system surgery.
Confuser physics is explicitly scoped out — Lane I introduces the
`TargetClass` enum and the `TargetKinematics::FromTakeoffProfile`
bridge so Lane J can land per-class dispatch without breaking
on-disk fixtures, but Lane I makes no per-class physics claims of
its own. Naming policy (per current memory state, Shahed-class /
platform names allowed in default code paths) is honoured;
overclaim guards remain active.
