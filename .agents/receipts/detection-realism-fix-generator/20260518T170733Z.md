## Problem

`detection/reports/auc_table.md` reported AUC ≈ 1.0 for all five detection
models (CFAR, LightGBM, CatBoost, TCN, Transformer) across all horizons. The
result was unbelievable — diagnostic forensic audit traced it to label-
correlated shortcuts in the training-data generator.

## Diagnosis

### A. Five hardcoded label-conditional branches

All in `crates/echoforge-dataset/src/ml_training.rs::build_frame_products`,
lines 887–944 of the pre-fix version:

| # | Lines | Shortcut |
|---|---|---|
| 1 | 887–891 | `positive_rise = 7.5 * (1 - exp(-t/16))` added to `snr_db` for positives only |
| 2 | 931–937 | `range_direction = -0.78` for positives, random `[-0.18, 0.28]` for negatives |
| 3 | 939–944 | Deterministic altitude climb formula for positives, random scatter for negatives |
| 4 | 919–923 | `tbd_track_score` adds `+0.42 * progress` for positives, `+0.05` constant for negatives |
| 5 | 903 | `normalized_snr = (snr_db + 14) / 44` propagates shortcut #1 |

### B. Bifurcated generator architecture (architectural, not directly fixed here)

`synthesize_takeoff_episode` (`crates/echoforge-radar/src/sim.rs`) IS called
for every record — tensor products flow through the physics simulator. But
the streaming features (`build_frame_products`) are generated from envelope
statistics + RNG, not from the physics simulator. This is a deeper
architectural issue; this receipt covers only the in-frame branch removal
(Phase 1) and envelope-range harmonization (Phase 1.5). The full unified-
physics refactor (`synthesize_takeoff_episode` → `synthesize_scene` with
generic `TargetClass`/`KinematicProfile`/`RcsProfile`/`MicroDopplerProfile`)
was deferred per coordination with codex's parallel Python v2 work — see
"Open architectural question" in `FUCKIT.md`.

### C. Envelope range non-overlap (Phase 1.5 target)

`sample_envelope` and helpers gave each class a non-overlapping observable
range. Examples:

- positive `radial_velocity_mps` ∈ `[-55, -24]`; bird ∈ `[-18, 18]` — no overlap.
- positive `initial_range_m` ∈ `[4800, 8500]`; bird ∈ `[300, 3500]` — no overlap.
- positive `base_snr_db` ∈ `[7, 14]`; bird ∈ `[-4, 9]` — overlap only `[7, 9]`.

Even after removing the five in-frame branches, single-feature AUC on these
envelope-leaked features would stay near 1.0.

## Changes made (Phase 1)

In `crates/echoforge-dataset/src/ml_training.rs::build_frame_products`:

1. Deleted the `positive_rise` term; removed `+ positive_rise` from the
   `snr_db` expression. `snr_db` now derives from
   `envelope.base_snr_db + family_noise - 3.8 * rfi_pressure - 2.2 * clutter`.
2. Deleted the class-branched `+0.42 * progress / +0.05` term from
   `tbd_track_score`. Score is now
   `0.18 * normalized_snr + 0.16 * doppler_scr_norm + 0.12 * persistence_norm - 0.20 * rfi_pressure`.
3. Replaced label-branched `range_direction` with class-neutral kinematic
   physics: `range_m = envelope.initial_range_m + envelope.radial_velocity_mps * time_s + small_jitter`.
4. Replaced deterministic altitude formula for positives + random scatter for
   negatives with class-neutral stochastic altitude:
   `altitude = envelope.altitude_m * (0.85 + 0.30 * unit_f64)`.
5. `normalized_snr` formula unchanged; honest because `snr_db` is now honest.

Inline comments added explaining each removal.
