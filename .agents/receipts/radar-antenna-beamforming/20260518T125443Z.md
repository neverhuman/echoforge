## Notes
- `DelayAndSumBeamformer` and `CaponStubBeamformer` keep their weight vectors as `Vec<num_complex::Complex<f64>>`. The crate's `num-complex` dep is pulled in without the `serde` feature, so these structs deliberately omit `#[derive(Serialize, Deserialize)]`; if the crate later wires up serialization for tuning files, enabling that feature is the right next step.
- `CaponStubBeamformer` is exactly that — a stub. It applies a pre-computed weight vector to channel IQ. The full sample-covariance inversion + MVDR weight estimation is intentionally deferred to a follow-up packet; the trait, struct, and call sites are wired so the swap-in is mechanical.
- Race note on `lib.rs`: at first read the file held the original module list; on second read (immediately before edit) the `micro-doppler-generator` packet had already inserted `pub mod micro_doppler_gen;` and its `pub use` block. I preserved both lines and inserted `pub mod antenna;` / `pub mod beamforming;` and the matching `pub use` blocks alphabetically alongside them. No other module declarations or re-exports were touched.
- The `micro_doppler_gen::tests::helicopter_produces_two_frequency_components` failure is pre-existing on the untracked sibling module and is outside the boundary of this packet.
