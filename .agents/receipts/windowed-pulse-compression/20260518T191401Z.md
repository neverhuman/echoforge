### Measured window performance (precise values)

Helper script `/tmp/measure.rs` reproduced the same correlator the
gate test uses and printed:

| Window                       | Length | BT  | Measured PSL | SNR loss |
|------------------------------|-------:|----:|-------------:|---------:|
| None (control)               |     64 |  64 |    -24.36 dB |   0.0 dB |
| **Taylor-35 nbar=4** (default)|    64 |  64 |  **-34.48 dB** | **-0.91 dB** |
| Taylor-35 nbar=4             |    128 | 128 |    -38.01 dB |  -0.91 dB |
| Hamming                      |     64 |  64 |    -36.34 dB |  -1.39 dB |
| Dolph-Chebyshev (-50 design) |    512 | 512 |    -46.76 dB |   not measured |

All five windows implemented and working:
- **`CompressionWindow::None`** — byte-stable with previous behaviour.
- **`CompressionWindow::Hamming`** — closed-form, endpoint 0.08 verified.
- **`CompressionWindow::Hann`** — closed-form, endpoint 0.0 verified.
- **`CompressionWindow::TaylorN35 { nbar }`** — Carrara/Goodman/
  Majewski 1995 §7.2.4 closed form, scipy-`signal.windows.taylor`
  parity. Default.
- **`CompressionWindow::TaylorN40 { nbar }`** — same formula at -40 dB.
- **`CompressionWindow::DolphChebyshev { sll_db }`** — naive O(N^2)
  IDFT of `T_{N-1}(beta * cos(pi k / N))`. Slow PSL convergence vs BT
  is a known finite-BT effect (Lynch 1997); the gate test uses
  length=512, BT=512 to land within ~3 dB of design.

The Taylor closed form was successfully implemented without falling
back to Hamming; no implementation caveats.

## Citations
- Harris, "On the Use of Windows for Harmonic Analysis with the
  Discrete Fourier Transform", *Proc. IEEE*, Jan 1978 — window
  function survey; provides the textbook Hamming endpoint value 0.08
  and Hann endpoint 0.0 used in the coefficient identity tests.
- Carrara, Goodman, Majewski, *Spotlight Synthetic Aperture Radar*,
  Artech House 1995, §7.2.4 — Taylor weighting closed form
  (`F_m` Bessel-zero ratio formulation, `nbar` passband ripples,
  `sigma^2` dilation factor). The Rust implementation in
  `taylor(length, sll_db, nbar)` follows this verbatim.
- Dolph, "A Current Distribution for Broadside Arrays Which Optimizes
  the Relationship Between Beam Width and Side-Lobe Level",
  *Proc. IRE*, June 1946 — original equi-ripple sidelobe taper.
- Lynch, "Time-Domain Window Properties" appendix in *Introduction to
  RF Stealth*, SciTech 1997 — slow PSL convergence of Dolph-Chebyshev
  with respect to time-bandwidth product, motivating the length=512
  test bound.
- Skolnik, *Introduction to Radar Systems*, 3rd ed., §6.5 — matched
  filtering and the role of amplitude weighting for range-sidelobe
  control; informs the C9 gate.

## Strict-open posture
No measured-truth claims. All sidelobe targets are bounds against
published textbook window references. The C9 gate asserts a physics
property of the *simulator's own* matched-filter output, not a
real-world receiver. The `low_snr_products_are_finite` regression in
`sim.rs::tests` still passes because the ~1 dB SNR cost of Taylor-35
is well inside the existing margin (and the test asserts finiteness,
not absolute magnitudes).

## Caveats / notes for downstream

1. **The Taylor-35 default costs ~1 dB of integrated SNR** (sum(w)^2 /
   (N * sum(w^2)) = -0.91 dB for nbar=4). Documented in the test
   `pulse_compress_taylor_peak_loss`; the SNR floor of any
   downstream detector should be loosened by ~1 dB if it was tuned
   against the raw matched filter.

2. **The peak amplitude of the compressed pulse drops by ~4-5 dB**
   when the Taylor-35 window is applied because the window's mean is
   ~0.6. This is *not* an SNR loss (the noise drops proportionally);
   integration / detection tests should look at peak / noise-floor
   ratios, not absolute peak magnitudes. The
   `c9_range_sidelobe_floor_after_taylor35` integration test
   includes an explanatory comment on this.

3. **Dolph-Chebyshev finite-BT convergence is slow.** Caller code
   that uses `CompressionWindow::DolphChebyshev { sll_db }` should
   keep BT >= 256 to land within ~5 dB of the design sidelobe level.
   Below that, the truncation tails of the LFM dominate and the
   advantage over Taylor-35 disappears.

4. **`RadarChain::pulse_compress` (the bare backend call) remains
   unwindowed.** Only `RadarChain::detect` applies the chain-level
   taper. This preserves byte stability for any existing code that
   compares raw matched-filter output across backends.

5. **`LfmChirp` did not get a `compression_window` field** because of
   Serde compatibility (the struct is constructed with explicit field
   literals in tests and deserialized from JSON elsewhere; adding a
   required field is a breaking change). Callers that want a
   pre-windowed reference go through
   `LfmChirp::windowed_samples(window)`. If Lane I (unified scene
   generator) needs to thread a window through a SceneDescriptor it
   can add a separate `compression_window` field on the *scene*
   struct and call `windowed_samples` at materialisation time.

6. **`tests/physics_correctness.rs` was created fresh in this
   worktree.** The main branch's working tree has a much larger
   pre-existing `physics_correctness.rs` from other lanes — when the
   parent merges Lane E it should concatenate the C9 tests into that
   file rather than overwriting it.
